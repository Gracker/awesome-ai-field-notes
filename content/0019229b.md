| 2075457839481708960 | yibie |  | 推荐这篇文章，https://t.co/QgQbJwhgZr 团队分享了一个 Agent 系统的关键架构模式——"睡眠计算"。Agent 执行任务时产生大量"尾气"（检索了什么、尝试了什么、哪里出错了），这些是学习的原材料，但绝对不应该在用户等待时处理。他们的方案是类比生物睡眠中的记忆巩固：在空闲计算上运行 Generator → Reflector → Curator 管道，让明天的 Agent 比今天更好，而今天没有任何任务变慢。

睡眠计算

一个 agent 在做真正工作时产生大量的"尾气"。每个任务留下原始痕迹：检索了什么、尝试了什么、哪里出错了、人类改了什么。这些痕迹就是学习的所在——但它以最差的形式到达：原始的、体积庞大的，发生在最差的时刻——一个用户正在等待回答的时候。

所以我们不在那时学习。我们在之后学习，在空闲计算上——就像一个人在过夜时巩固一天的工作。我们叫它睡眠计算。

热路径不是学习的正确位置

在推理时，有两样东西稀缺：延迟和注意力。用户正在等待，把清理上一次任务记录的每一毫秒花掉，就会让当前任务慢一毫秒。把混乱的 trace 提炼成干净、可复用的上下文，而用户看着——这是错误的权衡。

所以平台在推理时几乎完全不干这个。在任务运行中，它廉价地抓下原始痕迹然后继续。昂贵的那部分——把痕迹转化为下一个 agent 能用到的东西——完全在热路径之外进行，没有用户的时钟来消耗。

只有两个其他选择，两个都更差。把提炼放在内联，每个任务都要为清理上一个任务付出"税"，用户感受到的是延迟。或者永远不做，系统永远不学习，把每个任务产出中最有价值的东西扔掉。离线路径上的巩固，是你得到学习而不付出延迟税的方式。

为什么"睡眠"是正确的词

这里的类比不只是为了好听。生物记忆的巩固在结构上做的事情是类似的：白天原始的经历被重放和压缩成持久记忆，身体处于离线状态——正因为如果这些发生在清醒时间，会干扰行动。

把巩固转移到空闲时间做了同样的动作，为同样的原因。系统白天行动，晚上学习，两者互不干扰。工作保持快，因为学习等到了一个安静的时刻。

在无事发生时处理

在活跃任务之间，计算在闲置，没有用户在等。这就是睡眠计算运行的时刻。它取走近期工作的原始活动，把它巩固成结构化知识——程序化的笔记、修改、反复出现的模式，写回到上下文层——未来的 agent 将在那里找到它们。

这些本来在热路径上要消耗延迟的工作，在空闲循环上什么都不花。它改善了之后的每一次检索。明天的任务更快更好——因为处理跑在了没有人使用的时间上。今天什么也没有变慢。

把它变具体。在构建一份财报 Deck 时，一个 agent 留下原始痕迹：它打开的文件、它画的图表，以及一位专家的修正——数字应该是调整后 EBITDA、瀑布应该按季度滚动。在原始形式下，这是几百行事件日志，下一个 agent 根本用不了。睡眠计算读了它，在账户的上下文里写了一条持久的注释："此账户用调整后 EBITDA，瀑布按季度滚动。"下一个 agent 用一个句子读注释——而不是用一千行读日志。

管道做了什么

具体来说，巩固是一个管道。原始事件被提炼为候选观察。信号从噪音中提取——反复出现的修正保留，一次性的丢弃。保留下来的信号写进上下文存储，作为结构化的、可检索的知识，下一个 agent 在合适的时刻读到。

原始工作事件（痕迹、修正、观察）
          ↓
   提炼（原始到候选笔记）
          ↓
   提取信号（保留反复出现的，丢弃一次性的）
          ↓
   写入 .context（结构化、可检索）

Generator 提出更新，Reflector 批评它们，Curator 执行写入。运行在空闲计算上，按照组织、团队、个人三层并行运行。因为整个组织该学什么，和一个人的助手该学什么，是不同的巩固过程。一个属于所有人的模式写在层级的高处；一个只属于一个人的偏好留在他自己的范围里。

Generator、Reflector、Curator

核心是一个从近期研究借来的 loop。Generator 根据新活动提出对上下文的更新。Reflector 批评它们——一个提议中的教训是真的吗？和已知相容吗？值得保留吗？Curator 决定最终写什么，增量地写进存储。

这个 loop 的核心是克制。朴素地把 agent 注意到的所有东西都追加进去，会膨胀上下文成噪音和矛盾——噪音上下文检索效果更差，而不是更好。Generator-Reflector-Curator 循环保持了层在信号上成长，而不是在体积上。目标不是更大的存储。是一个更锋利的存储。

一致性是 Reflector 的真正工作。当一个新学到的教训与存储中的一条冲突时，两者都追加会让下一个 agent 面对两个答案却没有办法选择。Reflector 抓到了冲突，Curator 解决它——要么更新旧笔记，要么把新笔记范围限定在适用的场景。这样存储保持一致而不是积累矛盾。写入按照含义去重——同一个教训学到了十次，记录一次，用置信度而非体积来表示强化。

它何时运行

两个触发。一个定时节奏——每几小时的量级——按照固定节拍扫描近期活动。还有一个容量阈值——当未处理的活动积压到可配置的限度时触发，确保工作爆发后及时巩固，而不是等到下一次定时扫过。

稳态靠定时运行；尖峰靠阈值抓取。两者都不与线上推理竞争，因为两者都跑在空闲池上，和为用户提供服务的负载解耦。学习从来不从工作的延迟预算里借。

现在积累，以后呈现

这底下的一个设计选择值得单独提出来——它是"拥有数据，租用方法"原则在上下文层上的应用。积累知识和呈现知识之间有一条硬分界线。存储是持久的积累：组织学到了什么的原始和提炼记录。

如何把那个存储编译成给定提示的正确上下文，是另一个可替换的层。呈现侧被设计为可替换——今天的 prompt 优化方法、明天的——而不需要重新处理下面的存储。把上下文变成 prompt 的方法会持续改进。积累的上下文不需要每次方法更新时重建——这就是把两者分开的要点。

收益是具体的。当更好的 prompt 优化方法发布，你把编译器指向现有的存储，立即得到更好的 prompt——不需要重新处理一年来提炼出的上下文。你用最新的方法，保留数据不被动。这就是上下文层的整个理论——在这个操作细节中。

在睡眠中学习

廉价的洞察是 agent 只是通过工产生成改进自己的数据。昂贵的那部分是把原始数据变成可用的东西——而诀窍是永远不在热路径上为此买单。当用户等待时廉价抓取；当没有人用时在空闲计算上巩固；让积累持久而呈现可替换。明天跑你的任务的 agent 比今天的好——今天你的任何任务都没有因此变慢。这就是在睡眠中学习的全部意义。
