## 中文导读

Claude Code 后台子 agent 状态行改由 Haiku 5.5 依短笔记撰写：此前每 30 秒刷新并重读整段对话；新路径单次更新成本约降 99%，干活模型不变。官方口径：带后台子 agent 的会话少占约 5% 限额、多跑约 6% prompts；多数 Pro/Max/Ultra 与全部 Team/Enterprise 生效，CLI 门槛 v2.1.316+。此前 HN 企业遥测测到 agent_summary 占周花费约 16.4%；Anthropic 工程师回应官方遥测约成本 2%、请求 4%，承认对状态行仍偏贵，2.1.311 已修打不中 prompt cache 的贵路径。

## 为什么值得关注

## English Summary

Claude Code background subagents now write their 30-second status-line updates from short notes via Haiku 5.5 instead of re-reading the whole subagent conversation each time - about 99% less per update, with the subagent's working model unchanged. Anthropic reports sessions with background subagents use about 5% less of the usage limit and fit about 6% more prompts; available on most Pro/Max/Ultra and all Team/Enterprise plans, CLI v2.1.316+. Context: an HN thread (50284255) had measured via enterprise OTEL telemetry that agent_summary traffic was ~16.4% of estimated weekly spend and ~19.7% of API requests for heavy teams; an Anthropic engineer answered that official telemetry shows ~2% of cost and ~4% of requests for reporting users, admitted status lines were still too expensive, and noted v2.1.311 had already fixed the most expensive cache-missing summary path.

## 原文


## 原文（@ClaudeDevs, 2026-11-04 19:29 UTC）

Background subagents in Claude Code now use less of your usage limit.

A running subagent updates its status line every 30 seconds, and each update used to re-read its whole conversation. Now Haiku 5.5 writes it from short notes instead, so each update costs about 99% less.

## 背景补充（HN 50284255 与 Anthropic 工程师口径，本机研究材料核校）

- HN 帖标题：Claude Code regularly sends each background agent's transcript to its model（约 590 分/236 评）
- 企业 OTEL 遥测（secondary）：agent_summary 一周约占 16.4% 预估花费、约 19.7% API 请求（重度后台 agent 团队样本）
- Anthropic 工程师 edwinarbus：仅活跃后台 agent 约 30 秒一次 summary；官方遥测约成本 2%、请求 4%；「对状态行来说仍然偏贵」；2.1.311+ 已修 summary 打不中 prompt cache 的贵路径
- 版本锚：v2.1.316+ 起用 Haiku 短笔记路径；Threads（11-02 公测）与本条是会话经济学的两条路径
