## 中文导读

Brendan Gregg 在 LPC 2026 的分享（配套 PDF），核心论点：AI 正在改变性能工程的工作方式——过去工程师必须亲自理解大量专业工具的输出，现在可以让 Agent 负责解释、分析和执行；但要真正实现自动化，必须重新设计工具、工作流程和评测体系，而不能只依赖 Prompt。要点：(1) 架构分层——Prompt 定义任务约束、Skill 封装专业方法与防护、Agent 协调调用工具、子 Agent 并行分析，AI 应连接代码仓库/聊天记录/监控系统/Profiler 等外部上下文；(2) 闭环——先收集 CPU Profile，列出候选优化及预期收益/风险/权衡，由人选择方案后让 Agent 改代码、测试并创建 PR，把性能工程从「分析报告」推进到「可执行的工程改进」；(3) 工具输出要重设计——面向人的输出要变成更易解析、信息密度高、Token 低、保留证据的格式，以火焰图为例比较 PNG（人看快，AI 需视觉解析）/SVG（保结构但节点多时上下文开销大）/原始采样文本（信息全但 Token 贵）/结构化摘要（作者认为值得探索的折中）；(4) 漂亮的结果 ≠ 正确的结果——AI 能产出数量庞大排序精美的优化建议，却可能遗漏内核/虚拟化/硬件层问题；(5) 评测——用 100+ 个性能诊断练习（performance puzzles）评测不同版本 Performance Skills 的准确率，没有测量就可能高估 Agent 能力；(6) 挑战——AI 写的 eBPF/bpftrace 工具可能过长难维护、探针过多增加开销。

## 为什么值得关注

这是性能分析领域最有公信力的作者（火焰图发明者）对「AI + 性能工程」的系统性方法论：不是演示 prompt 技巧，而是指出传统工具输出面向人类专家，AI 时代需要重设计工具输出格式（火焰图的 PNG/SVG/原文/结构化摘要四方案对比是具体可抄的工程判断），并用 100+ puzzles 的评测集把「Agent 到底行不行」变成可测量问题。对做 agent 工具链、observability 和性能工程的人，这是罕见的一手经验输出。

## 关键信息

- 架构：Prompt（任务约束）→ Skill（方法+防护）→ Agent（协调执行）→ 子 Agent（并行分析）
- 闭环：Profile → 候选优化+收益/风险 → 人选方案 → Agent 改码/测试/PR
- 火焰图输出格式对比：PNG / SVG / 原始采样文本 / 结构化摘要（折中方案）
- 评测：100+ performance puzzles 测 Performance Skills 各版本准确率；测试集须能区分真诊断/似是而非/无效建议
- 挑战：AI 生成 eBPF 工具长、脆（多 kprobes）、开销大；生产安全（overhead/observer effect/crash）
