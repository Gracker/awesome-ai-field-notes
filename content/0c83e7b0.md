# 创始人手册：打造 AI 原生初创公司

> 原文：[The founder's playbook: Building an AI-native startup](https://claude.com/blog/the-founders-playbook)

## 核心要点

- **AI 已能独立完成研究、调研、编程和业务流程自动化**，抹平了创立公司和打造产品的门槛
- 初创公司进入新阶段，**不再必然意味着需要扩充团队、补充新技能，更不需要立刻去拉新一轮投资**
- 构思阶段核心：**先验证问题与解决方案的契合点，再动手开发**
- AI 可能强化确认偏误，需**刻意引入对抗性思考**来暴露漏洞
- Chat / Cowork / Code 按任务分工，过早扩张仍是头号杀手

## 四阶段生命周期

### 1. 构思阶段（Ideation）

**目标**：找到问题与解决方案的契合点（Problem-Solution Fit）

**通关条件**（三个问题都答是）：
1. 痛点真实且具体吗？
2. 你的方案能解决实际痛点吗？
3. 有足够的信号支持你动手开发吗？

**常见陷阱**：
- 把开发当验证——原型跑通不等于点子被验证
- 过早扩张——开发变得毫无阻力时最容易掉进陷阱
- 丧失客观性——AI 会顺着你的意思找证据，需要刻意对抗

**Claude 工具选择**：
| 场景 | 工具 |
|------|------|
| 快速交流、运营琐事 | Chat |
| 知识型工作（竞争分析、报告生成） | Claude Cowork |
| 智能体编程、代码库操作 | Claude Code |

### 2. MVP 阶段

**目标**：将经过验证的痛点转化为真实用户愿意使用的可用产品

**通关条件**：产品市场契合度（PMF）的真实证据
- 超过 40% 的活跃用户回答如果再也用不到这个产品，会非常失望（肖恩·埃利斯测试）
- 从推变成市场拉的转折点

**常见陷阱**：
- 智能体技术债（AI 生成代码结构漂移）
- 虚假 PMF（早期热度≠真实需求）
- 零阻力的范围蔓延
- 忽视安全

**关键实践**：
- 开发前先写 CLAUDE.md 定义架构约束
- MVP 边界必须白纸黑字记录
- 上线前进行安全审查
- 在第一个用户出现之前确立数据指标框架

### 3. 发布阶段

**通关条件**（三个要素）：
1. 增长是可重复的且由渠道驱动（单位经济效益清晰）
2. 产品能够处理生产负载（基础设施加固）
3. 运营不再卡在创始人这里（流程自动化到位）

**核心挑战**：技术债到期催收、PMF 保持、组织扩展能力

## 深度：AI 三杠杆

精益初创公司通过三个 AI 杠杆获得大企业般的能力：

### 对话式智能与研究调研
- 全领域随时待命专家
- 深度研究：竞品分析、市场规模估算、财务建模
- 文档起草：商业计划书、投资备忘录、产品需求文档
- 战略思考伙伴：扮演魔鬼代言人、事前验尸、情景规划

### 智能体编程
- 从点子到产品的时间被大幅压缩
- 创始人核心任务：决定做什么和为什么做
- AI 负责把地基打好，搭建面向用户的可用基础设施

### 流程自动化
- 按需召唤的全自动运营团队
- 交易推进→CRM 自动更新；一周结束→周报自动生成
- Claude Cowork 无缝接入现有系统，无需专人维护接口

## 深度：对抗性思考

AI 会顺着你的意思走，容易强化确认偏误。解药：

> AI 在帮你推翻一个点子时，和在帮你证明一个点子时一样卖力。

当对抗性思考暴露出想法的漏洞时，果断调整方向（Pivot）。
