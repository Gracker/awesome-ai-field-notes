# 每日 Agent 实践 · 2026-11-19

## 今日主题

Agent 自我改进的分水岭在准入这一环：写技能不验证，等于没写。

今天读的四篇工作指向同一个判断：让 Agent 反思失败、把经验写成技能，这件事本身产生不了收益，收益来自对每一条新技能的验证和回归测试。

证据先看 EMNLP 2026 的 GRASP。它在 MedAgentBench 上把 gpt-oss-120b 从 40.6% 拉到 88.8%，比五个自我改进基线中最强的还高 21 个点，但消融实验把功劳算给了三个部件：对比式提议生成、接受门控、硬性回归预算。技能写作本身没有贡献，论文原话是"不经验证的技能写作，不比不用技能好"。这句话解释了 Reflexion 式反思积累为什么常常涨涨跌跌：每条新经验都立刻写入，没有人检查它会不会弄坏以前做对的例子。GRASP 把自我改进当成对一个有容量上限的技能库做受控编辑，失败轨迹先按机制分组，比如打上"漏了日期过滤"的标签，与笼统的"答错了"区分开，每组生成增、改、删三类候选，候选必须在平衡探针集上做到修好的多于弄坏的、且新增回归为零才被接受，通不过就整轮放弃，库保持原样。

第二个坑在匹配。arXiv 上的 Assay 用随机掩码给每个技能算因果贡献，发现单个技能经常在 A 类任务上有正效应、在 B 类上有负效应，两相抵消之后全局指标看不出问题，所以按全局分数清理技能库没有用。它把生成和策展拆开，按任务类型压制预测为负的技能，AppWorld 最难分片上 DeepSeek-V3 拿到 69.3% 的任务完成率。SkillAxe 补上第三块证据：SkillsBench 上人类写的技能平均提升 16.2 个百分点，LLM 自己写的技能没有可测量的提升，差距出在写出来之后没人评估。SkillAxe 让同一个任务带技能跑一遍、不带技能再跑一遍，用行为差做四维诊断再自动改写，把 LLM 技能与人类技能之间 47% 到 67% 的差距补上了。

Skill-V 把这套逻辑推到边界：技能写成版本化的可证伪契约，修订只有在历史回放证据上不退步才能提交，ALFWorld 95.3%、WebShop 85.9%，库还比只增不减的基线更小。四篇拼起来是一条完整的因果链，反思负责找到错在哪，评估负责确认修正真的有效，回归测试负责确认没有弄坏别的，缺任何一环，自我改进就从受控过程退化成随机扰动。

对照本机 Hermes 的实践，技能库的增长恰好是慢速、人工门控的：humanizer 这类技能按需加载，是否保留由人决定，接受门控的角色由人承担，代价是覆盖慢，好处是几乎没有回归风险。GRASP 还给出适用范围的提醒，这套机制在任务重复出现、结果可验证的环境里有效，在开放式动作空间里效果持平，所以 cron 日报这类结构化任务适合攒技能，开放探索类任务别指望技能库兜底。自我改进做得好不好，先看准入这一环严不严。
