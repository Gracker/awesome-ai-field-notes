## 中文导读

LeadDev 与 CodeRabbit 的 AI 代码审查年度调查公开摘要：约 45% 的工程师把 code review 容量当成 AI 时代交付的最大拖累，约七成承认合并过自己并未完全理解的 AI 代码。这与哈佛/Jellyfish 平台数据研究里 review-to-merge 时间上升约 49% 的发现互相印证：写的成本被 agent 压下去之后，瓶颈系统性地挪到了审。HN 讨论帖约 332 分，评论分歧明显——有人整天只审 AI 代码并不喜欢，有人担心没人写代码之后没人有资格审，也有人认为 agent 找缺陷比人强但理解与所有权仍需人。调查数字当行业温度计用，别直接复制成团队流程结论。

## English Summary

The public summary of LeadDev and CodeRabbit's AI code review survey: about 45% of engineers name code review capacity as the biggest delivery drag in the AI era, and roughly 70% admit merging AI code they did not fully understand. This lines up with the Harvard/Jellyfish platform-data finding that review-to-merge time rose about 49% after agent adoption: as agents push down the cost of writing, the bottleneck systematically moves to review. The HN discussion sits around 332 points with split comments - some dislike spending days reviewing AI code, some worry that if nobody writes code nobody will be qualified to review it, and others distinguish agents' strong defect-finding from the human need for understanding and ownership. Treat the survey numbers as an industry thermometer, not as a ready-made team process conclusion.
