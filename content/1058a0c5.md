## 中文导读

MCP 官方把 Skills 立为正式扩展（扩展名 `io.modelcontextprotocol/skills`），beta 规范与文档发布在 modelcontextprotocol/ext-skills 仓库。扩展允许 MCP 服务器把工作流指令与配套文件作为 skill 暴露给客户端：skill 是含 `SKILL.md` 与可选支持文件的目录，沿用 Agent Skills 规范；发现与读取走 MCP——服务器必须实现 `skills/list` 与 `skills/get`，文件经既有 Resources 原语（`resources/read`）承载，清单必须带每个文件的 URI、SHA-256 摘要与字节数。关键边界：客户端经 `resources/read` 读到 `SKILL.md` 本身并不激活 skill，激活与否由宿主的 skill 加载逻辑决定。规范含 Security Considerations 章节，适用场景是代码评审、文档处理等多工具复用工作流。

## 为什么值得关注

MCP 生态从"工具列表"扩展到"可版本化的多步 playbook"，Skills/Tasks/Events 一批扩展里 Skills 直接对接 Anthropic 已经验证过的 Agent Skills 格式。对做 agent 基础设施的人，清单里的 SHA-256 完整性字段和"读取不等于激活"这两条是后续实现与安全审计的关键锚点。

## 关键信息

- 官方文档：modelcontextprotocol.io/extensions/skills/overview；规范仓库：github.com/modelcontextprotocol/ext-skills（specification/beta/skills.mdx）
- 扩展名：io.modelcontextprotocol/skills；服务器须同时声明 resources capability 与本扩展
- 必须实现 `skills/list`、`skills/get`；文件走 `resources/read`；可选 `directoryRead` 默认 false
- 清单字段：每个文件的 URI、SHA-256 digest、byte size；结果须带 resultType: complete、ttlMs、cacheScope
- skill 身份 = 服务器身份 + skill URI；名字只是标签、不保证唯一；建议 skill:// scheme 但不得只靠 scheme 判定
- 读取 `SKILL.md` 不等于激活；激活由宿主路由决定
- 配套：Skills Over MCP Working Group；另有 experimental 仓 modelcontextprotocol/experimental-ext-file-uploads

## English Summary

The Model Context Protocol project has published a beta specification for an official Skills extension (io.modelcontextprotocol/skills) in the modelcontextprotocol/ext-skills repository. The extension lets MCP servers expose workflow instructions and supporting files to clients: a skill is a directory containing a SKILL.md file plus optional supporting files, following the Agent Skills specification, with discovery and retrieval running over MCP. Servers must declare both the resources capability and the skills extension, implement skills/list and skills/get, and serve files through the existing resources/read primitive; manifests must carry each file's URI, SHA-256 digest, and byte size, with results including resultType, ttlMs, and cacheScope. Reading SKILL.md through resources/read does not itself activate a skill - activation stays with the host's skill loading logic. The spec includes a Security Considerations section and targets reusable multi-tool workflows such as code review and document processing.
