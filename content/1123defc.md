## 中文导读

工程师作者借同事 Emily 的「Brain Sandwich（大脑三明治）」框架回应 AI 时代工程技能萎缩问题（即 Simon Willison 说的 Meat Proxy：把整个脑子从工作里摘出去全权委托 AI）。框架三步：AI 之前先用脑——动手前先读代码、理解现场，不需要完整实现计划，但要有大致方向，否则 AI 会把你偏向错误方向、甚至让你去解一个本来不存在的问题；然后放心全权委托 AI，「毫不羞耻地完全 delegating 这一段」；AI 之后再用脑——方案回来时你已有判断力分辨它是对的、做过头了、还是在解错的问题，送人 review 前把工作变得可评审：读 diff、评估复杂度值不值、好好写 PR 描述。经验法则：如果你解释不清楚改了什么、为什么改，它就还没准备好给别人看。

## 为什么值得关注

把「人机分工」落成一个可执行的三明治顺序：理解先行、委托居中、可评审性收尾，而不是含糊的「要有判断力」。

## English Summary

An engineering blog post relays a teammate's 'Brain Sandwich' framework for working with AI without letting engineering skills atrophy (the 'Meat Proxy' failure mode of delegating entire work to AI). Three layers: brain first - read and understand the code before directing the agent (a rough direction suffices; otherwise AI biases you toward the wrong problem, or a problem that was never yours to solve); AI in the middle - fully delegate that stretch without shame; brain again - judge the returned solution (right? overbuilt? wrong problem?), then make the work reviewable before human review: read the diff, weigh whether the complexity is worth it, write a real PR description. Rule of thumb: if you can't explain what's changing and why, it's not ready for review.
