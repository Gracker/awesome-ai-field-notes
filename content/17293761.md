## 中文导读

Android agent 以用户权限读取应用与网页内容并代为操作，却无法可靠判断内容来源。作者检查的 WebView 无障碍字段只暴露宿主应用，不暴露浏览器内部可得的文档 origin，agent 走这个接口无从判断一个对象出自哪个文档；在未修改 WebView 上的复现得到相同结论。两个原型验证来源信息对授权的作用：应用来源监控基于系统无障碍日志的签名来源记录拦截带副作用的调用，测试运行中拦下全部选中的攻击性写入，代价是误伤读过不可信内容后的正常发送、并把来源记录带进后续干净任务；基于修改版浏览器的 WebView 来源引用门在 24 次试验里没有让 agent 选中任何被禁对象。作者写明边界：两个原型都还算不上集成防御，WebView 门还缺浏览器侧认证投递与选中内容/来源的原子捕获。

端侧 agent 权限模型的现状基线：间接提示注入场景下「内容来源」是授权缺失的一环，对 Android 无障碍通道的度量可以直接引用。

## English Summary

Android agents act on content whose provenance they cannot verify: the WebView accessibility fields expose only the host application, omitting document origins available inside the browser, so an agent reading through this interface cannot tell which document supplied an object (reproduced on unmodified WebView). Two prototypes test provenance for authorization: app-source monitoring via signed provenance records in system accessibility logs blocked all selected offensive writes (at the cost of false positives after untrusted reads); a WebView provenance-reference gate on a modified browser produced zero forbidden selections in 24 trials. The authors are explicit that neither is an integrated defense yet.
