## English Summary

Agentic Algorithm Engineering (AAE), a Claude Code and Codex skill from Heidelberg's Algorithm Engineering Group, hands the design-analyze-implement-experiment cycle to an autonomous agent: every experiment starts from a falsifiable hypothesis with predicted effect size, correctness assertions are agreed during setup, changes land as minimal commits, and only changes that get faster while staying correct are kept. On established open-source codes: VieCut 8.9x faster with cuts unchanged, KaHIP kaffpa 3.9x faster with partition quality preserved, pseudoflow max-flow 3.0x, FREIGHT 1.82x with bit-identical output, ParHIP 1.61x byte-identical. Each accepted change ships as a numbered patch plus a per-hypothesis PDF report (paper: arXiv 2609.07204). For agent builders the interesting part is the reusable contract: benchmark, metric, assertions, budget fixed upfront, then the agent runs alone.

Algorithm Engineering is a cycle of design, analysis, implementation and experiment, driven by falsifiable hypotheses. AAE hands this cycle to an autonomous agent. During setup you agree with the agent on the benchmark, the metric, the correctness assertions and the budget; then it runs on its own.

A falsifiable hypothesis: "changing X will improve the metric by roughly Z, because ..."

A minimal change, committed to Git, with the correctness assertions checked.

Run the benchmark; keep the change only if it is better and still correct, otherwise revert.

**One patch per accepted change**Numbered Git patches in `patches/`, each with its hypothesis, easy to review and apply.

**A PDF report**The trajectory of the metric and one page per tested hypothesis: intuition, prediction, measurements, verdict.

From the report of the KaHIP `kaffpa` session: 122 experiments, 69 hypotheses, 41 patches, 3.9x faster in total.

| Before each experiment | the agent's next idea | a proposed mutation | a falsifiable hypothesis with its predicted effect |

| Correctness | the metric | the evaluator score | assertions agreed with you, checked after every change |

| What you get | improved script and log | best program and population | one patch per change, a PDF report, lessons in a shared knowledge base |
