## 中文导读

这条推转译并介绍 Earendil Engineering 的《How Compaction Works in Pi》（8 月原作）：编程 agent（Pi、Claude Code、Codex 一类）的上下文窗口装不下历史记录时，会调用一次独立的 LLM 请求，对早期历史做结构化摘要（目标、进度、关键决定），近期消息原样保留。

工程取舍是重点：压缩会破坏前缀缓存（prefix cache），但能让长任务继续；缓存命中率与上下文余量是相反方向的力。理解这一点就能解释 Pi / Claude Code 长会话里“上下文换了一层”的现象。回复区补了两条实践：其一，压缩最怕把“已确认事实、未完成目标、验收闸门”压成看似完整的摘要——硬闸门是压缩后先让 agent 只输出这三栏，任一缺失就停，不准继续改代码；其二，长会话里最占空间的常是旧读档和测试输出，先用确定性函数把它们换成一行占位，常常就不用叫模型摘要整段对话，前面的决策原文也还在。

## 关键信息

- 原文：Earendil Engineering《How Compaction Works in Pi》（8 月），本推为完整中译介绍
- 机制：独立 LLM 请求摘要早期历史（目标/进度/关键决定）+ 近期消息原样保留
- 代价/收益：破坏前缀缓存 vs 长任务可继续；缓存命中率与上下文余量方向相反
- 实践闸门（回复区）：三栏 checkpoint（事实/目标/验收闸门），缺一即停
- 实践技巧（回复区）：确定性占位替换旧读档/测试输出，推迟整体摘要
