## 中文导读

全双工语音模型会抢话、会接话，但把对话能力变成任务能力是另一回事：用户改口后要及时调工具、改参数。Duopra 的诊断是前后端分离架构里执行可以卸载，但没发出去的请求无法执行、发一半的请求会带偏后端——Full-Duplex-Bench v3 流水线里多数失败发生在领域工具执行之前。做法是把后端当工具，前端用自包含自然语言请求调用，直接调用与委托共享动作接口；三段训练：协议 SFT、奖励及时完整执行的全双工 RL、只训 projector 修复 talker 条件化。同一后端下 Pass@1 从 4.7% 到 44.7%，直接调工具 47.7%，换 DeepSeek 后端 49.3%，FDB v1.0 三个接管率也提升。

## 为什么值得关注

语音 agent 的全双工能力正在从"对话自然"往"任务可执行"演进，Duopra 把这步跨越拆成了可训练的三段流程，并用 Pass@1 从 4.7% 到 44.7% 的对照说明瓶颈在接口设计而非后端能力。对做语音 agent、实时交互系统的人，前后端共享动作接口这个设计是可以直接借鉴的。

## English Summary

Full-duplex interaction models handle natural turn-taking, backchannels and interruptions, but completing tasks further requires task agency: timely tool invocation and argument revision after user corrections. Duopra's diagnosis: in frontend-backend agent architectures execution can be offloaded, but unsent requests cannot be executed and incomplete ones misdirect the backend - on Full-Duplex-Bench v3, most failures of a streaming pipeline occur before a domain tool executes. Duopra treats the backend as a tool, accepting a self-contained natural-language request, with direct calls and backend delegation sharing one action interface and requirements for faithful initiation and correct execution. Three-stage training combines protocol SFT, full-duplex RL rewarding timely and complete execution, and projector-only repair of talker conditioning after thinker updates. With the same backend, Pass@1 rises from 4.7% to 44.7%; Duopra reaches 47.7% calling tools directly and 49.3% with a DeepSeek backend, and improves three FDB v1.0 takeover rates over the base model.
