## 中文导读

Anthropic 披露其模型发现并利用 Linux 内核 IPv4 TCP 握手路径的 use-after-free（CVE-2026-98432，CVSS 9.8）：内核把 IP options 不拷贝移交新 socket，并发处理重传时读已释放内存。模型自行写出两阶段 exploit：竞态泄露内核地址绕过 KASLR（实测 48 分钟），再溢出改写回调指针以 root 执行命令（再 5 分钟）；竞态失败只是单连接失败，可无限重试。exploit 需服务器开 MPTCP 监听（Go 默认开启）；上游 10 月已修（4 行），Ubuntu/RHEL 滞后。

## English Summary

Anthropic disclosed that its model found and exploited CVE-2026-98432, a use-after-free in the Linux kernel's IPv4 TCP handshake (CVSS 9.8; the upstream fix credits Xinyang Ge): the kernel hands IP options to the new socket without copying, and a second CPU servicing a retransmitted request can read freed memory. After initial prompting, the model wrote a working two-stage exploit: the race leaks a kernel address to defeat KASLR (48 minutes in Anthropic's test), then an overflow rewrites a callback pointer for root command execution (5 more minutes); a lost race fails only that connection, so retries are free. The exploit needs a multipath TCP listener - Go programs open one by default; IPv6 is unaffected. Upstream fixed it in October with a four-line commit; Ubuntu and RHEL lagged other distributions.

## 关键信息

- 上游修复：git.kernel.org e3f33b0a1d89（4 行，Eric Dumazet），5.10.272/5.15.223/6.1.190/6.6.159/6.12.113/6.18.56/7.2.10 均已带
- 发行版状态（截至 10 月底）：Ubuntu 全系与 RHEL 8/9/10 仍 vulnerable；Debian、SUSE、Amazon Linux 已修
- 缓解：升级内核并重启，或禁 MPTCP、用 nftables 丢带 IPv4 options 的包；IPv6 不受影响
