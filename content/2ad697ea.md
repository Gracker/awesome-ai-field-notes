## 关键要点

- 作者把市面 agent memory 插件归纳为同一架构：读会话记录、切 snippet、入向量库、每次 prompt 检索 top-5 注入、再配一个搜索工具；各家只是叠加 token-burning 的"功能"修补同一缺陷架构。
- 五个结构性问题：相似度检索分不清哪条正确/最新/缺失；snippet 丢掉上下文与动机；把过去当真理（代码库天天在变）；agent 不知道自己不知道什么、不会主动搜索；上万条 embedding 不可审计。
- 替代方案是文档式记忆：像人类团队一样把知识写下来维护，而非更努力地回忆过去。AGENTS.md 之外需要一整套活的文档体系（指令、spec、调研、索引）。
- agentic 循环从 prompt → build → forget 变为 prompt → consult → build → update：工作前查 brain，工作后更新过时文档、补缺失文档。
- 作者实现为开源插件 Operator Memory（github.com/aerovato/operator-memory），纯 Markdown 文档，无向量库、无 embedding、无后台 daemon，已使用一年以上。

## English Summary

"Agents don't need memory. They need documentation" argues that the entire agent-memory plugin ecosystem shares one flawed architecture - go through session transcripts, generate snippets, insert into a RAG database, retrieve top-5 on every prompt, plus a search tool - and inherits the same failure modes: similarity search cannot tell which snippet is correct, current, or missing; snippets lose context, motivations, and environment; the past is treated as truth while the codebase changes daily; agents cannot search for what they do not know; and a store of thousands of embeddings is unauditable. The author's alternative is document-based memory: people handle knowledge by writing things down, so projects need real living documentation beyond a lone AGENTS.md rather than better recall over past conversations.
