## 中文导读

Cursor把Projects从单人agent舰队升级为多人工作区：团队成员加入同一Project，共享任务板展示谁在做什么、各人的agent跑哪条任务及其对应PR。每人仍保留与自家coordinator/worker的一对一私聊和本地上下文，其上叠加需求文档、图表、技术规格、mockup等共享context层，一处聊天里的决策对Project内所有agent可见，新人入组即继承。跨队友agent消息按untrustedinput处理：分享个人文件或connector数据前先征得同意，侧聊不能给人发消息、不能过secrets、可读任务板不可改。

## 为什么值得关注

Cursor Projects 多人化：共享任务板 + 团队 context + 跨队友 agent 消息（untrusted）

这是「团队 agent 共享状态」第一次被写进一线 coding agent 的产品面：9 月 Projects 解决的是一人指挥多 agent，这次解决的是多人多 agent 同仓时的上下文孤岛与冲突。官方博文一手信息完整（共享任务板、团队 context、跨队友 agent 通信三段式），docs 机制补充到 Agent Store 路径与 untrusted 语义级。

## docs 机制补充（cursor.com/docs/agent/projects）

- 共享两块：task board（list + board）+ shared context = 一个 Agent Store（UI 名 Context，路径 /cursor/stores/self），全体成员的 agent 可读写
- 个人侧：每人 own chat + coordinator + workers，bills as them（按本人计费）；个人 store /cursor/stores/user 仅本人 agent 可见，偏好与 skills 跨 Project 跟随
- agent 间消息：标成 agent input、按 untrusted input 权衡；分享个人文件/connector 数据前先问；不打断主 chat，进侧聊「Chat with {{name}}'s agent」；侧聊只能可读/停/归档，不能给人发消息、不分享 secrets/credentials/tokens、可读任务板不可改、不能问用户问题/request access/连源控/管 routines
- 谁能加入：同一 Cursor team + invite，需 Project 仓库权限；Privacy Mode (Legacy)、self-hosted 机器上的 Project、archived Project 不可；分享需 team 账号 + Cursor 3.26.13+；Projects 基础能力需含 Cloud Agents 的套餐（Premium 及以上/Teams/Enterprise，Enterprise 客户端 3.21.9+）
