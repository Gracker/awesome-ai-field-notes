## English Summary

Migrating Android/iOS apps to HarmonyOS NEXT requires a full rewrite in ArkTS; LLM translation that compiles gives no functional assurance. HMOS Migrator is an agentic pipeline that reads the source app, generates an ArkTS project, and validates by replaying recorded interactions on a real device. Scoring is quality estimation without a reference implementation, using only the source app's recorded behavior and pipeline artifacts; seven weighted metrics are each constructed so reduced measurement cannot raise the score. Over twelve runs on six open-source apps, structural completeness reached 83.3-100% while on-device behavior (4.3-63.1%) and UI fidelity (21.1-63.2%) remain the limits; scores improve +0.45 points/day (R2=0.44, p=0.019). The record-replay plus artifact-scoring design transfers to GUI-agent regression testing.

## Abstract (arXiv)

The migration of applications written for a different platforms like Android or iOS to HarmonyOS NEXT requires a complete rewrite in ArkTS. Although LLMs automate the translation of source constructs into ArkTS, syntactic compilation is not enough and functional assurance is a critical open challenge in HarmonyOS NEXT migration. We present HMOS Migrator, an agentic pipeline that reads an application's source code, generates an ArkTS project, and validates the result by replaying recorded interactions on a real device. We cast the scoring problem as quality estimation without a reference implementation; we score a migration using only the source application's recorded behaviour and the artifacts produced by the pipeline. We define seven weighted metrics, each constructed so that reduced measurement cannot artificially raise the score. Over twelve runs across six open-source applications, the pipeline's structural reproduction is high (completeness 83.3-100.0%), while on-device behaviour (4.3-63.1%) and UI fidelity (21.1-63.2%) remain the primary limits. Scores improve steadily over time: +0.45 points per day overall (R2=0.44, p=0.019).
