## English Abstract

Esri engineering blog argues that AI orchestration should live in the browser instead of round-tripping every state change back to a server. The browser already holds live map state, layers, and user interactions, which makes it a natural runtime context for agents: zero-latency DOM events, local credentials, and the avoidance of REST serialization on every step. Web GIS workloads overlaying layers, selecting features, drawing geometry benefit most because the agent consumes the same in-memory state the UI does. The post frames this as a Web-GIS-first design, but the same pattern generalizes to any rich-client product where the UI is the canonical source of truth.
