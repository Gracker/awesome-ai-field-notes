## 中文摘要

Simon Willison 10月3日短文：coding agent / personal agent 把搭一个能花钱的应用的门槛压到几乎为零，但大量按量付费 API 只有超预算发警告邮件的软上限，一夜跑出几千美元账单才发现。他主张 pay-by-use 服务必须默认提供硬预算上限（触线直接停服务并返回错误），想冒险的人显式勾选自担费用选项；点名 AWS 最该做这件事，并引用 AWS 9月16日刚发布的 monthly spend limit（项目触线当月暂停，仍限量开放）和 Google Cloud 7月的 Spend Caps 作为行业转向的证据，还希望 agent 以后推荐服务时优先选带硬上限的供应商。

## 关键要点

- 软上限（超预算发邮件）对 agent 时代不够用：等用户早上读到邮件，损失已经发生。
- 硬上限必须默认开启：触线停服务 + 返回错误；解除限制需要显式 opt-in 并自担费用。
- AWS 9月16日上线 monthly spend limit（项目触线当月暂停），文档提示仍在限量发布；Google Cloud 7月推出 Spend Caps。
- 作者期待 agent 主动推荐带硬预算上限的供应商，并警告新手避开无上限服务。

## English Summary

In a short Oct 3 post, Simon Willison argues that coding and personal agents drastically reduce the friction of spinning up code that spends money, while most pay-by-usage APIs only offer soft caps (a warning email), so a rogue service can burn thousands of dollars overnight. He calls for default hard budget caps - cut the service off and return errors at the limit - with an explicit opt-in checkbox for people willing to live dangerously. AWS finally launched monthly spend limits on Sept 16 (projects pause at the limit, still rolling out), Google Cloud shipped Spend Caps in July, and he hopes agents will start biasing toward recommending capped providers.
