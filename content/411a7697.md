forzAlex 回应 OpenAI Pando：在他的团队规模下瓶颈不在 Git 而在阅读近 30 天 develop 分支落地 2377 个 commit，约每天 72 个（不含 merge），多数由 agent 编写由他一人审批并行 agent 靠规则管住：每 agent 独立 worktree各自的文件 allowlist作者不自审，最近一次 merge 零冲突漏过的不是 Git 冲突而是语义错误：本地过生产挂的 migration理由错误的通过测试从不被调用的代码口头决策被代码悄悄改回，多数带通过的测试结论：agent 产能随基础设施扩展，人的注意力不随扩展

## 为什么值得关注

工具接口优化的自动化下一步：Anthropic 指南靠人手改描述，这篇把'怎么改描述'本身变成可训练任务，且不依赖执行轨迹——冷启动和隐私受限场景可用。150+ 工具目录下 60.89% 的成功率提升意味着工具检索/选择误差是主要退化源，这与 agent 生产环境里工具越来越多的体感一致。

## 关键信息

- 论文：arXiv 2602.20426，2026-02-23 提交、2026-04-29 更新，cs.AI；作者 Ruocheng Guo / Kaiwen Dong / Xiang Gao / Kamalika Das（方法名 Trace-Free+）
- 问题：多数工作在改 agent（更大模型、更好提示、微调），性能却在工具接口质量处平台化；工具描述为人类开发者而写，带有 agent 无法消解的歧义，候选工具越多越严重
- 既有方法两个瓶颈：每个新 API 要重跑多阶段流水线（合成查询 → 执行 agent 采轨迹 → 标注 → 多次调用强 LLM）；逐工具独立优化，限制对未见工具的扩展与泛化
- 方法：Trace-Free+ 课程学习框架，把 trace-rich 场景学到的"什么使工具描述有效"的监督渐进迁移到 trace-free 部署；配套从真实 API 出发的数据合成流程，构建大规模高质量工具接口数据集
- 结果：StableToolBench 上候选工具扩到 150+ 时，scaling 实验中精度退化降低 29.23%、平均查询级成功率提升 60.89%；跨域免重训练泛化；与 agent 微调收益互补

## English Summary

Alex (@forzAlex), founder/CTO, responding to OpenAI's Pando announcement: at his team's scale the bottleneck is not Git but reading. Last 30 days: 2,377 commits to develop, ~72/day excluding merges; agents write most of them, he approves them. Parallel agents are tamed by rules: a separate worktree per agent, a per-agent file allowlist, and no author approving their own work - last merge had zero conflicts. The bugs that slip through are not Git bugs: migrations that pass locally but break in production, tests passing for the wrong reason, code written but never called, and agreed decisions quietly reversed in code. None fail the build; most arrive with passing tests. His conclusion: agent capacity now scales with infrastructure; human attention does not.
