## 中文导读

作者把一台 32 位 RISC-V CPU（RV32IM + Zba + 大数运算单元）编译进原版 Qwen 3.5 4B 的权重，占用模型前面 11 层，全程无训练——编译器把"读寄存器/加法/零跳转"这类电路步骤直接写成注意力头、前馈单元与 DeltaNet 头。RAM 用模型自己的 Gated DeltaNet 状态：gate=1、beta=1、one-hot key 编码之后，每次写恰好覆盖一行、查询精确读回，线性 RNN 变成可寻址内存。CPU 通过官方 riscv-tests、程序与 qemu 一致，1800 万条指令自由运行零错误；能在前向传播里跑 C 与 MicroPython，无需任何外部运行时或工具调用。长整数算术 NUPA 从 48.6% 提到 100%，与挂 Python 工具持平。另附实验性文件系统：文件名哈希进 1024 个槽、最多 512 个文件约 5.3 万 token，跨会话持久，事实召回 90% 对 30%。限制：checkpoint 翻倍到 18.8GB（多为零填充）、需 RvChat 驱动启动固件并隔离 trace token、每条指令折合几个解码 token，L4 上批量执行约 3200 CPU token/秒。

## 为什么值得关注

Gated DeltaNet 这类线性 RNN 的状态通常被当作"会遗忘的模糊记忆"。这篇的关键一步是把 gate=1、beta=1、one-hot key 三个开关组合起来：状态矩阵的每一行都变成确定性内存单元，写入精确覆盖、读取精确返回，且状态大小不随上下文长度增长——这是 KV cache 做不到的。作者自认新意不在 delta-rule 充当记忆（Schlag et al. 2021 已证明），而在把它做成生产模型里精确、可寻址、可靠到能跑整机 CPU 的东西。在权重里编译出能跑 C/MicroPython 的 CPU，意味着"模型自带确定性计算"可以完全不依赖工具调用与沙箱：长整数算术从 48.6% 到 100% 是直接证据，且重放约 23 万个输出位零失配、普通文本与基座的 KL 散度仅 6e-4，说明 CPU 与原模型行为几乎互不干扰。两个续作方向更值得留意：混合架构模型可以把推理藏进 RNN 状态躲避 CoT 监控；反过来，编译进权重的组件也能当监控与可解释性工具（模型关不掉的 in-weight monitor、interpretability answer keys）。

## 关键信息

- 结构：原版 Qwen 3.5 4B + 编译进权重的 32 位 RISC-V CPU（RV32IM + Zba + bignum 单元），占模型前面 11 层（模型本身 32 层）；无训练，编译器直接改写每个权重
- RAM 机制：GDN 状态 + gate=1 + beta=1 + one-hot key，精确单行覆盖/读回；Qwen 3.5 四分之三的注意力层用 Gated DeltaNet
- 指令执行：每条指令折合几个生成 token（ADDR 命名内存行、VAL 携带值、STEP 结束指令），token 流即 CPU 执行轨迹
- 正确性：通过官方 riscv-tests，程序与 qemu 一致，1800 万条指令 free-running 零错误；约 23 万输出位重放零失配；普通文本与基座 Qwen 的 KL 6e-4（噪声底线 5e-4）
- 算术：NUPA 长整数 48.6%→100%（持平 Python 工具）；DeepMind 集 div_big 97.5%（基座 72.5%）、mul_big 97.5%（基座 55%）、mul_div_multiple_longer 100%、add_or_sub_big 97.5%
- 文件系统（实验性，rv-store 分支）：文件名哈希到 DeltaNet 状态里 1024 个槽（冲突顺延），正文按每行 8 token 链式存于其他头；上限 512 文件 ≈ 5.3 万 token；跨会话持久（保存/加载状态即可），改后事实召回 90% vs 贴回旧对话的 30%，与 Python 记忆工具相当（83.3% vs 78.9%）
- 限制：checkpoint 18.8GB（约基座两倍，多为零填充）；需 RvChat 驱动启动固件、避免 trace token 泄入 Qwen 层，尚不能用普通 generate() 运行；速度慢（每指令数个 token），L4 批量执行约 3200 CPU token/秒；单张 24GB GPU 可跑
- 资源：GitHub divagr18/qwenputer；Hugging Face 与 ModelScope 提供 Qwenputer、Filesystem 两个模型
- 续作：RNN 状态藏推理躲避 CoT 监控；编译权重作监控工具（in-weight monitor、interpretability answer keys）

## English Summary

Qwenputer is a stock Qwen 3.5 4B with a 32-bit RISC-V CPU (RV32IM + Zba + a bignum unit) compiled directly into 11 of its layers — no training involved; a compiler sets every weight, turning circuit steps like "read this register" or "jump if zero" into attention heads, feed-forward units, and DeltaNet heads. RAM is the model's own Gated DeltaNet state: with gate=1, beta=1, and one-hot key encoding, each write overwrites exactly one row and queries read back exactly, making the linear-RNN state exact, addressable memory of constant size regardless of context length. The CPU passes official riscv-tests, matches qemu, and ran 18 million free-running instructions error-free; it runs C and MicroPython inside forward passes with no external runtime or tool use, lifting NUPA long-integer arithmetic from 48.6% to 100% — on par with giving Qwen a Python tool. An experimental in-weights filesystem (1,024 hashed slots, up to 512 files ≈ 53k tokens) persists across chats with 90% vs 30% fact recall. Costs: an 18.8GB checkpoint (~2x, mostly zero padding), an RvChat driver to boot firmware, and a few decoded tokens per instruction (~3,200 CPU tokens/s batched on an L4).
