## English Summary

Code-executing LLM agents submit code blocks issuing several API writes; when a block fails mid-way, the agent rewrites and continues, and the recovery itself can harm external state. From recorded AppWorld trajectories, a stratified sample of 200 episodes across ten models yields 145 partial executions confirmed by database state; 30 of 143 with determinable outcome are followed by harmful recovery persisting at run end - weighted estimate 24.6%. Two-thirds duplicate an effect; the rest delete user data or make a wrong first-time write. A repeated-call rule finds 75% of duplications but only 41% of all harm. Model-supplied operation IDs do not reduce harm (new ID per same operation); content-derived IDs, evaluated counterfactually, would match every harmful write in 14-18 of 30 cases. ## Source Excerpts

### Abstract (opencli arxiv paper, 2026-11-26)

Code-executing LLM agents submit blocks of code that issue several API writes. If a block fails after some of its writes have taken effect, the agent rewrites the block and continues. In a stratified random sample of 200 candidate episodes across ten models, 145 are partial executions confirmed by the database state. 30 of 143 confirmed partial executions with a determinable outcome are followed by a harmful recovery, and its violation remains at the end of the run, which gives a stratification-weighted estimate of 24.6%. A rule that searches for repeated calls finds 75% of duplications but only 41% of all harm.
