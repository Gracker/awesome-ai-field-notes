## Summary

Switch 2 当前最新固件 23.0.1 上的首个软件越狱（作者自称），software-only、tethered：能以普通 sysmodule 和内置 fs sysmodule 身份跑任意原生代码。用户态入口弃 WebKit n-day 线（XOM+PAC+CFI 挡住「浏览器 RW 到任意 IPC」），改打 Switch 1 游戏 SmileBASIC 的解释器：Codex 找到 REMOVE 命令 32 位整数下溢，memmove 三参数全部回绕，把数组前 8 字节拉进数组——SmileBASIC 数组前 8 字节恰是自身指针，越界读写到手再升级 ROP。提权走 fs sysmodule 路径规范化的 0x301 字节堆溢出，受害分配是 BufferedStorage 缓存条目，改 PID 为 1 拿 FullPermission。信任链断点在「fs 自己保证内容与 NCA 头哈希一致」：fs 内任意读写后在 ldr 与 fs 之间把域表 ExeFS 对象换掉，签名校验用的仍是原文件系统哈希。人机分工记录诚实：越狱本体约两周人力，agent 找到关键整数下溢与受害分配、双线并行，一天 vibecode 出 Mario Kart World 模组。

ns2jb is the first software-only jailbreak for Switch 2 on the latest firmware 23.0.1, enabling arbitrary native code as any ordinary sysmodule including the built-in fs sysmodule. The WebKit n-day entry dies against XOM+PAC+CFI; the working path exploits a 32-bit integer underflow in the SmileBASIC interpreter's REMOVE command (found by Codex), turning an underflowed memmove into arbitrary read/write via the array's self-pointer, then ROP. Privilege escalation abuses a path-normalization heap overflow in the fs sysmodule with a BufferedStorage cache entry as the victim allocation; the trust chain falls because fs guarantees its own content consistency - with fs compromised, the domain-table ExeFS object is swapped between ldr and fs, so signature checks still validate against the original filesystem hash. The author's honest human/AI division: about two weeks of substantive human work; agents found the underflow and the victim allocation, ran two exploit lines in parallel on two machines, and vibecoded a Mario Kart World mod in a day.

When removing items from an array, the interpreter checked position + count <= array.length , but the sum could wrap and become negative. To fill the gap created by removing elements, it’s supposed to shift the remaining elements left, like so: memmove ( backing + position * 8 , // start of the gap backing + (position + count) * 8 , // elements after the gap (length - position) * 8 // bytes to copy ); Say we have a string array R of length 4, and we run REMOVE R,&H60000000,&H3FFFFFFF . position + count wraps to 0x9fffffff . As a negative signed 32-bit integer, it’s less than array.length . The multiplications by 8 also wrap, so we end up performing memmove(backing, backing - 8, 32) , pulling the previous 8 bytes into the array. Since a pointer occupies what would be the length field of R[0] , the string length is enormous, and we can perform reads and writes out of bounds. We read and write to memory by copying to and from substrings of R[0] . ### 一手全文要点

**Amazon Threat Intelligence identifies PHP2Shell exploitation prior to public disclosure in MadPot（aws.amazon.com，CJ Moses，2026-10-21）**

- 核心事实：MadPot 遥测观测到 10-17（披露前四天）的 PHP2Shell 利用尝试，来源 IP 属商业匿名化网络；embargo 内打蜜罐 + 匿名化来源 → 判定为威胁 actor 行为，但 actor 如何在披露前获得利用信息不明。
- 披露日时间线：最早 PoC ≈10-21 02:00 UTC（embargo 解除前 12 小时）；02:00-08:00 UTC 多批利用尝试来自不同匿名基础设施，payload 与匿名化选路各异 → 多个 actor；技术分析进行中，无法确认在真实系统上是否成功。
- 补丁后：数小时内新 PoC 出现并立即打到蜜罐；「PHP2Shell is now being broadly exploited in the wild」。
- 三条防守建议：调查起点用最早观测到的利用而非披露日（本次至少从 10-17 起）；面向互联网关键漏洞的补丁/缓解按小时计，7/30 天 SLA 假设的延迟已不存在；投资不依赖 CVE 签名的检测——第一波利用总在签名之前。
- 结构判断：patch → working exploit 时间因 AI 辅助分析（补丁 diff/公告 → exploit）结构性缩短；过去「少数能人写 exploit、其余等现成」的依赖在弱化。AWS 自报每分钟分析 200B+ 事件。

**There isn't an easy exploit for this PHP vulnerability（eliastaylor.com，Elias Taylor，2026-10-21）**

- 立场：漏洞真实且重要，但「远没有传播中说的那么好打」，与 Log4Shell/Heartbleed/RoR YAML 完全不同级；置顶编辑强调「该打补丁还是要打」。
- 观察：GitHub 上「字面意义上几千个」PoC 仓库，没有一个能打穿 vanilla PHP 实例；作者邀请读者自起 Docker 受影响版本、亲手跑 PoC 验证（别让 LLM 代跑）。
- 归因：五年前大家能分清可利用性，现在「人被自己的 LLM 骗了——LLM 说你有 exploit，其实没有」。
- 对照组（作者认定的「真完蛋」CVE）：RoR YAML（发个坏 body）、Log4Shell（设 UA 为 ${jndi:ldap:}）、Shellshock（改 env）、Heartbleed（要 Content-Length 10^7）——都是单请求触发。
- 与 Wiz「一个研究员一周」叙事的关系：两者不矛盾——头部研究员能做出来 ≠ 武器化成品人人可得；同时假 PoC 海量让防守方按 PoC 数量评估风险会失真。

**Farewell, France（quad9.net，2026-10-22）**

- 事实：法国法院 10-21 就 beIN（卡塔尔体育媒体，法国办公）版权诉讼判 Quad9 败诉，要求对法国用户阻断一组域名；罚款从 €580k/天降到 €1k/天，至 11-14 累计 €24k（不含诉讼费）。
- 结构性死结：按国家阻断需要辖区映射——Quad9 免费免注册、不存用户档案，无法判定哪些用户适用该判决；全球阻断技术上可行（并入恶意域名库）但让法国判决对所有用户域外生效。
- 压力账：20 起同类待判案件罚款未评估，叠加未来同类诉讼，「不作为」不可持续 → 11-24 起退出法国。
- 立场原文要点：递归 DNS 是中立被动服务；盗版应在内容托管源头处理；迫使无关第三方破坏互联网基本原则是误导且适得其反；不能遵从判决同时忠于使命。

**Jailbreaking the Switch 2 / ns2jb（pepsipu.com，Sammy Hajhamid，2026-10-18）——知识星球成稿底稿**

- 能力面：Switch 2 当前最新固件 23.0.1 上首个软件越狱（作者自称），software-only、tethered；能以普通 sysmodule 与内置 fs sysmodule 身份跑任意原生代码——homebrew、逆向改游戏、备份存档、MMIO 访问外设；演示为 Codex 一天改出的 Mario Kart World（加角色、实机比赛视频）。
- 用户态入口（WebKit 线，弃）：自定义 WiFi captive portal 打 WebKit n-day 可拿浏览器内执行，但 Switch 2 的 XOM + PAC + CFI 让「浏览器 RW → 任意 IPC」走不通（找不到 gadget / 签不出指针 / 调用点全被 CFI 检查）。

- 信任链断裂点：ldr 用两层签名锁内容（任天堂签 main.npdm 权限 + 开发者钥 → NCA 头签名 → 头哈希 → 文件系统哈希 → 可执行内容），但「fs 送上的内容与 NCA 头哈希一致」由 fs 自己保证；fs 内 ARW 后，在 ldr 请求 ExeFS 与 fs 处理后续请求之间把域表中 ExeFS 对象换成自建临时文件系统（原始 main.npdm + 任意 main）——签名校验用的仍是原文件系统的哈希与签名；时序控制靠把 fs 等待的 loader IPC handle 换成 SmileBASIC 控制的 event handle；用 ro 的 NPDM（可映射可执行内存）启动任意代码。

## 知识星球候选

ns2jb：Switch 2 的第一个软件越狱，以及一份诚实的人机分工记录

Sammy Hajhamid 10 月 18 日发布 ns2jb，Switch 2 当前最新系统 23.0.1 上的第一个软件越狱（作者自称），software-only、tethered：能以普通 sysmodule 和内置 fs sysmodule 的身份跑任意原生代码，于是可以跑 homebrew、逆向和修改 Switch 2 游戏、备份存档、通过 MMIO 直接摸外设。演示环节是一天改出来的 Mario Kart World——往游戏里加自选角色、实机跑比赛。整条链从浏览器之外的一个 BASIC 解释器开始，一路走进任天堂的加载器信任链内部，是目前把 Switch 2 安全设计讲得最完整的一份一手材料。

用户态入口先试了常规路线：用自定义 WiFi captive portal 触发一个 WebKit n-day，拿到浏览器内代码执行。然后撞上 Switch 2 的三件套——XOM（代码页不可读）、PAC（指针签名）、CFI（调用点类型检查），从「内存读写」到「任意 IPC 调用」之间找不到 gadget、签不出指针、调用点全被检查，这条线放弃。作者改打 Switch 1 游戏 SmileBASIC：Switch 1 没有 PAC、根信任早破（代码可解密阅读），而这款游戏在 3DS 时代就出过 smilehax。Codex 在解释器里找到一个 32 位整数下溢：REMOVE 命令检查 position + count <= array.length，但两者之和会回绕成负数通过检查；示例里一条 REMOVE 让 memmove 的三个参数全部回绕，变成 memmove(backing, backing - 8, 32)，把数组前 8 字节拉进数组——而 SmileBASIC 里任何数组前 8 字节恰好存着指向数组自身的指针。之后把 R[0] 当字符串用，长度字段就是那个指针值，越界读写到手，再升级到 ROP。

从用户态到内核服务的跳板是内置 fs sysmodule。GetEntryType 的路径规范化里，形如 /..\ 的带反斜杠父目录分量会走进一个分配 0x301 字节临时堆缓冲的 helper，而路径本身可以比缓冲长——溢出。Codex 找到的受害分配是 BufferedStorage 的缓存条目：dirty 位置位时对文件的读写会跟随缓存指针，把这个指针改掉就拿到 fs 进程内任意读写。再把 SmileBASIC 连接对象里保存的 PID 改成 1，进程直接拿到 FullPermission，dump 出内部存储和全部普通 sysmodule 的代码。

全文最值得记的是加载器这一步。理论上 ldr 的两层签名把可执行内容锁得很死：任天堂签 main.npdm 的进程权限、开发者钥签 NCA 头哈希、哈希定文件系统内容、文件系统哈希定可执行文件。但链条有一环靠组件自己保证——「fs 送上的文件系统内容与 NCA 头哈希一致」这件事，执行者是 fs 自己。攻击者拿到 fs 内任意读写之后，在 ldr 请求 ExeFS 与 fs 处理后续请求之间，把域表里的 ExeFS 对象换成自建临时文件系统（放原始 main.npdm 加任意 main），签名校验用的还是原文件系统的哈希与签名，直接以任意 NPDM 权限启动自己的代码；时序控制靠把 fs 等待 loader 消息的 IPC handle 换成 SmileBASIC 持有的 event handle。再用有可执行内存映射权限的 ro 的 NPDM 启动代码，普通 sysmodule 级执行到手。信任链在密码学上没输，输在「内容一致性由被攻破的组件自己担保」这一环。

人机分工的记录比 exploit 本身更值得留：作者明确说那句「set a goal to jailbreak the switch 2. make no mistakes」是玩笑配文，Codex 没能自主完成越狱，本体是约两周的实质性人力。但 agent 在链路里干的都是实事——找到 SmileBASIC 的整数下溢、找到 BufferedStorage 受害分配、WebKit 与 SmileBASIC 两条线用两台机器并行推进、游戏模组一天写完。和本周 PHP2Shell 的「AI 把利用开发成本打下来」并读，这是一份少见的中间态样本：结构性、跨系统的信任链断点还是人找的，模式化适配与旁支工程 agent 已经能接。对做平台安全的人，教训是通用的：任何「由组件自己保证内容一致」的环节，默认该组件被攻破后整个链条作废——fs 如此，任何把校验和执行放在同一信任域里的设计都如此。
