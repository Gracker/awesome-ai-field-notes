## 中文导读

POMA（Pwn-Oriented Model Assessment）针对安全基准只看最终 pass/fail 或粗粒度阶段里程碑的问题，提出过程级评测：固定任务输入、工具接口、目标环境、反馈格式与执行预算，在统一执行基线上隔离底座 LLM 本身的能力，从运行时证据测量中间状态与状态转移。四个前沿底座模型在 55 个 CTF Pwn 题和 10 个真实漏洞复现任务上暴露出沿利用链的持续能力衰减：从漏洞知识到可执行实现、从客户端动作到已验证目标状态、从失败定位到精确修复，以及跨迭代修订都在掉。真实软件上模型还要同时满足格式、语义、差分与崩溃同一性约束。基准目录、过程度量评估器与样例 harness 已开源（github.com/maple-pwn/poma-release）。

## 为什么值得关注

现有安全基准把拿到 flag 当终点，得分无法区分是模型能力还是外部 agent 脚手架。POMA 把评分点移到中间状态与转移，用统一基线解耦底座与脚手架，并定位利用链在哪一段断掉——选底座模型、设计漏洞利用 agent、判断能力衰减发生在哪，都能直接复用这套实证基础。

## English Summary

POMA (Pwn-Oriented Model Assessment) is a process-level evaluation methodology and platform for base LLMs on vulnerability exploitation. Existing security benchmarks score binary pass/fail outcomes or coarse stage milestones, obscuring fine-grained failure dynamics across long-horizon execution and conflating intrinsic base-LLM capability with external agent scaffolding. POMA fixes task inputs, tool interfaces, target environments, feedback formats and execution budgets under a unified execution baseline and measures intermediate states and transitions from runtime evidence. Across 55 CTF Pwn challenges and 10 real-world vulnerability reproduction tasks, four frontier base LLMs show persistent capability attrition along the exploitation chain: from vulnerability knowledge to executable implementation, from client-side actions to verified target states, from failure localization to precise repair, and across iterative revisions. On real-world software, models further struggle to satisfy format, semantic, differential and crash-identity constraints simultaneously. Benchmark catalogs, the process-measurement evaluator and a sample harness are publicly released.
