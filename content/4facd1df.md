## 笔记全文（每日 Agent 实践 · 2026-11-18）

### 今日主题
生产级 Agent 记忆系统的现状：分层结构趋同，混合检索成为默认，写入和过期仍是薄弱环节。

讨论 Agent 记忆时最常见的假设是：上下文窗口够大，记忆设计就可以省掉，把历史全部塞进去就行。Mem0 在《State of AI Agent Memory 2026》里给的判断相反：注意力在长跨度上会衰减，窗口再大，工作记忆的可靠性也不会随窗口线性上升，所以 2026 年的生产系统普遍把记忆当成独立组件来建。报告里另有一处细节值得记下：他们的检索栈并行跑三路打分，语义相似、关键词、实体匹配，融合后的分数高于任何单一信号。

混合检索的收益有独立证据。一项覆盖约 2.5 万问答对、横跨四个数据集的评测（arXiv 2511.04696）发现，词项检索和稠密检索结合的效果好于两者单独使用；另一项跨八个对话数据集的研究给出同方向结果。只靠向量检索，在 2026 年已经算不上合格的默认配置。

检索之外，更麻烦的是写入和更新。5 月发布的 STALE 基准（arXiv 2605.06527）测的就是这个痛点：Agent 明明检索到了更新后的证据，行动时仍沿用旧假设。Vectorize 的一篇长文把生产中记忆故障的样子描述得很具体：系统不会崩溃，只是自信地记错、忘掉关键决策、把上周的状态套到今天的请求上。这篇文章把记忆系统拆成五件事：什么该写入、怎么分类、旧记忆怎么修订或过期、检索时给多小的证据集、验证记忆是否真的改善了结果。对照这个拆解，检索是其中最不会被省掉的一环，写入策略和过期规则才是最常被省掉的。

分层结构本身倒有了收敛的答案。MemGPT 论文（arXiv 2310.08560）借用操作系统的分页思路，把常驻上下文的核心记忆和外部可检索的档案记忆分开，由模型自己调用函数在层间搬数据。Letta 在此基础上做成可编辑的记忆块，每块有标签、内容和字符上限，并配一个休眠时运行的整理 Agent 负责晋升降级。他们的经验里写明了一条反模式：把所有内容自动晋升等于没有分层，价值来自取舍。

这一点在本机 Hermes 上有直接体会。MEMORY 块有约 2200 字符的硬上限，每记一条新内容就得先删旧的或改写得更短。字符上限看起来是限制，实际是逼着系统持续做筛选的机制，和 Letta 用字符上限约束记忆块是同一个设计判断。

arXiv 上一篇 2026 年的综述（2603.07670）结尾有句实话：模型选型要经过几个月的反复评测，记忆架构常常只分到一个下午。从今天读到的材料看，这个下午应该拆开花，一半给检索的混合信号，一半给写入、修订和过期规则。检索配错了丢一次分，写入规则缺失会持续地、悄悄地丢分，后者更值得先补。
