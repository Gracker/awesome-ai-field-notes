### 1) Carbon, Hydrogen, Neon, Oh My!（Google Orchestrator）
- **Gemini 4 Hydrogen**（约 Nov 12）：更快更便宜的 agentic/coding 向模型；**Neon**（约 Nov 18）：能力接近/对标 Carbon、价速中间档。
- **Antigravity Orchestrator**：在**单一 agent、单一 context** 内切换背后模型——规划端用 Carbon/Neon/Argon 读代码写计划，执行端 **Hydrogen** 改代码、构建、测试；失败（如检查连续失败）交回规划端改计划。对比「多 agent 拆分」或 Claude Code advisor / Codex subagents / Sakana Fugu 等不同编排哲学。
- 页述 API 价：Hydrogen **$1.50 / $7.50** per M in/out；Neon **$3.00 / $15.00**；上下文合计至约 **1M**，默认输出至约 **64k**。
- 页述 Artificial Analysis 数字（Issue 正文）：Hydrogen high ≈ **51** Index（近 Argon 50）；Hydrogen xhigh **54**、**14.9 min/task**、**$3.16/task**；Neon xhigh **61**、**$6.44**、**25.8 min**；Carbon high **60**、**32 min**、**$5.48**（introductory price）。Terminal-Bench：Carbon+Hydrogen Orchestrator 接近 Carbon 成功率，并 **快约 19%**、token 配额约 **少 24%**。注意 Hydrogen xhigh 总输出 token 可能更高（页述 304M vs Carbon 205M over Index tests）。
- 速度页述（AA）：Hydrogen 最高档约 **173 tok/s**，Neon 约 **99 tok/s**。

### 2) llama.cpp Makes It Official
- **llama.cpp 1.0.0** + **ggml 1.0**（Hugging Face 上的 llama.cpp 团队）。
- 里程碑含义：维护者认为足够成熟稳定；继续支撑 Ollama、LM Studio 等本地栈；GGUF、量化、多后端（CUDA/Metal/Vulkan/CPU 等），页述 **150+ architecture variants**。
- 1.0 增量页述：支持包括 **Kimi-K3.1 Pro** 等新模型、内置 server 的 TTS、聊天 UI 重做；server API 风格对齐 OpenAI/Anthropic「够用但不强保证兼容」。
- 生态：GitHub Octoverse 页述贡献者增长独立项目约第 5、整体 engagement 约第 3；ggml 团队 2026-02 加入 HF；硬件方赞助 runner 等。

### 3) How the "Token Tax" Hurts Non-English Users
- CLEAR（Coalition for Language Equity in AI Research）研究：同义内容在不同语言上的 token 数（因而 API 费用）最大可差约 **17×**；FLORES-200 上对 tokenizer 做 max/min ratio 评级（≤3× 为 A，>12× 为 F）。
- 页述例子（GPT-5 tokenizer 口径）：同一句英 / 马拉雅拉姆 / 阿姆哈拉 ≈ **13 / 26 / 78** tokens。
- 页述评级：不少前沿通用模型 tokenizer 得 **F**（含彼时 GPT-5、Llama 3.3 等）；**Gemini/Gemma 家族约 B（研究内最佳档）**。并引用 2023 Petrov et al.、Ahia et al. 及 2024 中文超长噪声 token 等工作。
- 产品含义：新兴市场用户在连通性/算力之外再叠一层「语言税」，会把查询推向拉丁文或少数全球语言。

### 4) Communicating Agents' Thoughts（StateBridge）
- 论文方向：Sheffield 的 Yanwen Peng 等 — **StateBridge**：基于**同一 LLM** 的多 agent，在无需额外训练的前提下，把发送方最后一层 hidden state 旋到接收方可消化的输入空间（对齐 token embedding 统计、幅度、并与最近 embedding 做 70/30 混合等），用末 **64** 个 token 的 hidden 代替整段文本 handoff。
- 角色链页述：planner → critic → refiner → judge（角色定义参考 LatentMAS）。
- 结果页述：在 Qwen3 4B/8B/32B 与 OLMo3-7B-Think 上，平均高于「单 agent / 纯文本四 agent / LatentMAS」；相对最强基线约 **+2.4–2.9 pp**；GPQA-Diamond 上 Qwen3-8B：**StateBridge 52.5%** vs LatentMAS 45.5% vs 单 agent 39.9%。代码 **Apache 2.0**。
- 启发：64 个变换后的向量若能替代全文消息，检索文档/工具输出的「向量手递」值得跟。
