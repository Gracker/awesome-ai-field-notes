## Source Highlights

- An NES CPU compiled into the weights of a stock Qwen3.5 model: the 6502 CPU (the core of the 2A03 chip), its 2 KB of work RAM, and a cartridge's program ROM run inside a standard Qwen3_5ForCausalLM checkpoint. Nobody trained these weights; a compiler computed every one.
- When you play a game, the model predicts the CPU's execution log one token at a time; a small host program plays the rest of the console — draws the picture, reads the controller, fires the vblank interrupt.
- nesformer builds on Qwenputer (Divyansh Agrawal), which compiled a CHIP-8 and then a RISC-V CPU into Qwen3.5-4B, reusing its compiler and central trick: the model's Gated DeltaNet state is the machine's memory.
- Verification: in bundled test games every CPU token came from the model, and every frame matches a conventional 6502 emulator's output exactly, including Super Mario Bros. World 1-1 and a full homebrew game's title screen and first level.

## English Summary

nesformer compiles an NES — its 6502 CPU, 2KB of work RAM, and cartridge program ROM — into the weights of a stock Qwen3.5 model (Qwen3_5ForCausalLM). Nobody trained these weights; a compiler computed every one, reusing Qwenputer's compiler and its central trick: the model's Gated DeltaNet state is the machine's memory. At play time the model predicts the CPU's execution log one token at a time while a small host program plays the rest of the console — draws the picture, reads the controller, fires the vblank interrupt. In bundled test runs every CPU token comes from the model and every frame matches a conventional 6502 emulator exactly, including Super Mario Bros. World 1-1. A striking data point for what deterministic behavior can be baked into untrained LLM weights, extending the CHIP-8 and RISC-V Qwenputer line.
