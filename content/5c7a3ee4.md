## English

When I built menugen ~1 year ago, I observed that the hardest part by far was not the code itself, it was the plethora of services you have to assemble like IKEA furniture to make it real, the DevOps: services, payments, auth, database, security, domain names, etc...

I am really looking forward to a day where I could simply tell my agent: "build menugen" (referencing the post) and it would just work. The whole thing up to the deployed web page. The agent would have to browse a number of services, read the docs, get all the api keys, make everything work, debug it in dev, and deploy to prod. This is the actually hard part, not the code itself. Or rather, the better way to think about it is that the entire DevOps lifecycle has to become code, in addition to the necessary sensors/actuators of the CLIs/APIs with agent-native ergonomics. And there should be no need to visit web pages, click buttons, or anything like that for the human. It's easy to state, it's now just barely technically possible and expected to work maybe, but it definitely requires from-scratch re-design, work and thought. Very exciting direction!

## 中文

当我大约一年前构建 menugen 时，我注意到迄今为止最难的部分绝不是代码本身，而是需要像组装宜家家具一样把各种服务拼装起来才能让它真正运行——也就是 DevOps：服务、支付、认证、数据库、安全、域名等等……

我非常期待有一天只需要告诉我的 AI 代理："构建 menugen"（参考那篇帖子），它就能直接工作。从头到尾一直到已部署的网页。代理需要浏览大量服务、阅读文档、获取所有 API key、让一切正常运行、在开发环境调试，然后部署到生产环境。这才是真正困难的部分，而非代码本身。换一种更好的理解方式是：整个 DevOps 生命周期必须变成代码，同时还需要为 CLIs/APIs 配备适合 AI 原生的交互接口。而且人类无需访问网页、点击按钮或做任何类似的事情。说起来容易，现在勉强在技术上也刚刚变得可能、可以期待它能 work，但绝对需要从零开始重新设计、工作和思考。这是一个非常令人兴奋的方向！
