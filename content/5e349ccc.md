## 中文正文

Qwen 发布 3.6 系列首款旗舰级编程密集模型 **Qwen3.6-27B**，27B 参数即达到旗舰级代码能力，在所有主要编程基准测试中超越 Qwen3.5-397B-A17B（397B 总参数 / 17B 激活的 MoE）。Qwen3.5-397B-A17B 在 Hugging Face 上需要 807GB 存储，而 Qwen3.6-27B 仅需 55.6GB。

Simon Willison 试用发现：使用 Unsloth Qwen3.6-27B-GGUF:Q4_K_M 量化版本（16.8GB）和 llama-server，即可本地运行并生成高质量代码（如"画一只骑自行车的鹈鹕"的 SVG），生成速度约 25 tokens/s。

这是开源模型代码能力的重要里程碑——采用密集架构而非 MoE，在较小参数量下实现高代码性能，且 27B 规模首次使旗舰级编程能力可以在消费级硬件上运行。开源与闭源代码能力差距已收窄至约 6 个月。

## English Original

Big claims from Qwen about their latest open weight model: **Qwen3.6-27B** delivers flagship-level agentic coding performance, surpassing the previous-generation open-source flagship Qwen3.5-397B-A17B (397B total / 17B active MoE) across all major coding benchmarks. On Hugging Face Qwen3.5-397B-A17B is 807GB, this new Qwen3.6-27B is 55.6GB.

I tried it out with the 16.8GB Unsloth Qwen3.6-27B-GGUF:Q4_K_M quantized version and llama-server. The results are outstanding for a 16.8GB local model — generating an SVG of a pelican riding a bicycle at ~25 tokens/s.

This is a significant milestone: a dense model (not MoE) achieving flagship-level coding in a size that runs on consumer hardware. The gap between open-source and closed-source code capability has narrowed to approximately 6 months.
