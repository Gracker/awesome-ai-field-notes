## 中文导读

Anthropic 为 Messages API 推出 Message Threads 公测（beta header message-threads-2026-08-12）：长会话 agent 首轮传全文，之后每轮只传新消息加前次 response id，Claude 每轮仍读全部历史，token 用量与账单科目不变。官方数字：50 万–100 万 token 请求的中位 TTFT 约 −35%，请求体中位从约 800KB 降到 1.8KB；Claude Code 对多数用户默认开启。线程存于加密内存不落盘，闲置 5 分钟过期、最长保留 1 小时；线程不自动做 prompt cache，二者是「传全文」与「缓存复用」两套时钟；无 list/read/delete 线程 API，不适用 ZDR/HIPAA。可用平台含原生 API、AWS、Microsoft Foundry、GCP Anthropic managed，标准费率与限额。

## English Summary

Anthropic's Messages API Message Threads entered public beta (2026-11-02): long-running agents send the full conversation once, then only new messages plus the previous response id, while Claude still reads the full thread each turn - token usage and billing unchanged. Anthropic reports median TTFT down about 35% for 500k-1M token requests and median request bodies shrinking from ~800KB to ~1.8KB; Claude Code enables it by default for most users. Threads live in encrypted memory (not disk), expire 5 minutes after the last request, are kept at most 1 hour, do not automatically create prompt-cache entries (two separate clocks), lack list/read/delete APIs, and are not offered under ZDR or HIPAA terms. Available on the native API, AWS, Microsoft Foundry and GCP Anthropic managed at standard rates.
