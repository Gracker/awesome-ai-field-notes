# Tracking down a Zsh history data loss bug

> Source: https://michael.stapelberg.ch/posts/2026-08-09-zsh-history-truncation-bug/
> Author: Michael Stapelberg

## Summary (EN)

Michael Stapelberg documents a years-long investigation into a Zsh history file truncation bug where recent entries would occasionally disappear from `~/.zsh_history`. He walked through inotify, fanotify, fatrace, auditd, SystemTap, and bpftrace, discovering that Zsh reads old history, writes to `.zsh_history.new`, then renames over the old file. Since file monitoring tools didn't expose PIDs reliably, he ultimately patched Zsh to crash on the suspicious state and analyzed the core dump. The fix shipped in Zsh 5.9.2 (July 2026). The article is a masterclass in narrowing down intermittent data-loss bugs: from file event monitoring to forced crash + core dump analysis.

Michael Stapelberg 记录了对 Zsh 历史文件丢失 bug 的多年排查过程。他依次尝试 inotify、fanotify、fatrace、auditd、SystemTap、bpftrace，发现 Zsh 会读取旧历史、写入 `.zsh_history.new` 再 rename 覆盖原文件。因为文件监控工具无法可靠暴露 PID，他最终修补 Zsh 让可疑状态直接崩溃，再分析 core dump 定位触发路径。修复已随 Zsh 5.9.2 发布。
