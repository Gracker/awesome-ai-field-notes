## English Summary

Claude Code v2.1.283 (released Sep 25) leans toward managed and enterprise deployments: the new availableModelsMatch managed setting with "exact" restricts availableModels entries to the exact version named, so new releases stay blocked until listed, plus a deniedModels blocklist; gateway hint headers gain x-claude-code-prompt-id so LLM gateways can group requests serving one user prompt; OTEL tool.output span events can opt into MCP, WebFetch and WebSearch content; /doctor prompt-audit audits CLAUDE.md files, skills, agents and commands for prompting patterns written for older models; plus a gateway load_test_mode (requests built and signed but not sent upstream), a Bedrock Mantle upstream, and MCP fixes spanning background progress notifications, leftover stdio servers, and stateless-server 404 lockouts.

## English Source Excerpt

> What's changed
> 
> -   Added `x-claude-code-prompt-id` to the gateway hint headers so LLM gateways can group the requests that serve one user prompt; opt in with `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`
> -   Added `availableModelsMatch` managed setting: with `"exact"`, an `availableModels` entry allows only the model version it names, so new releases stay blocked until listed
> -   Added `deniedModels` managed setting to block specific models, even when `availableModels` allows them
> -   Added MCP tool, WebFetch and WebSearch outputs to the `tool.output` OpenTelemetry span event when `OTEL_LOG_TOOL_CONTENT=1`
