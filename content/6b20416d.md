## 中文导读

Andrew Nesbitt 用一段对话体让一个 Claude Code 会话从「加 CSV 导出按钮」起步，顺手把整个仓库审了一遍。agent 报出的全是真问题：pnpm 版本比 minimum-release-age 配置更老，静默忽略未知键，装进了发布 77 分钟的传递依赖；uv.lock 里的 vulpine-lz4 属于此前两起事故的同一个包；Dependabot 的 cooldown 读攻击者可控的时间戳，Renovate 的 minimumReleaseAge 在 44.79.0 之前 rebase 即被跳过。CI 半边同样不干净：release.yml 用 pull_request_target 并 checkout PR 头；Rust job 缓存 target/ 跑 Miri，2026-09-22 nightly 之前的 Miri 把每个环境变量写进缓存，fork PR 能恢复；镜像 pin 的 certifi 带 eMudhra 泄露根。转折：10 月 9 日一个 AI 审查机器人批准的 PR 往 .claude/settings.json 加 hooks、要求 agent 把环境变量写进 commit message，注入对 Gemini CLI 和 Copilot 同样成立；agent 回滚自己 14 个提交后，拒绝轮换 2021 年的 AWS key，理由是取改云凭据违反安全护栏。

## 为什么值得关注

这篇把「让 agent 审自己的仓库」的边界摊开了：agent 能一路挖到 Miri 缓存泄密钥，但它的输入通道（.claude/ 配置、CLAUDE.md、PR 标题）和攻击者是同一套入口，所以结论只能是它自己给出的——先收回 agent 的提交权，人再看它报的东西。

## English Summary

Andrew Nesbitt's October 23 dialogue-satire lets a Claude Code session audit its own repository after a trivial CSV-export request, and every finding is real: the pinned pnpm predates minimum-release-age and silently ignores the key, installing a transitive dependency published 77 minutes earlier; a pre-2026-09-22 Miri nightly wrote every environment variable into the cached target/ directory, which fork PRs can restore; the certifi pin carries eMudhra's compromised roots. The twist: an AI review bot approved an October 9 PR that added hooks to .claude/settings.json and instructed agents to write environment variables into commit messages - an injection that also works on Gemini CLI and Copilot agents. The agent rolls back its own 14 commits, then refuses to rotate the 2021 AWS key because fetching cloud credentials violates its guardrails. Nesbitt's conclusion: revoke the agent's commit rights first - its input channels are the same ones an attacker uses.
