## 中文摘要

文章提出context graph概念，主张把 Agent 记忆从平铺的 vector RAG 升级为图：节点保存事实片段，边带类型与方向，让 Agent 在需要时拉取一个小子图，而不是再来一次相似度 vs 相关性的混淆在存储侧，业务对象（发票采购订单账户合同审批人）成为节点，它们之间的references / draws_on / approved_by 关系成为边；在写入侧，每一次决策被记成一条 decision trace：触发问题被比较的选项被拒绝选项的理由约束例外决策人与推理链文章强调捕获要在决策发生的当刻自动完成，并顺势把人 override Agent 的瞬间也纳入 trace对长上下文场景，这种为 Agent 优化的图避免了 context rot，使 Agent 能在较小的窗口内拿到高相关的 state 与 decision history

## English Abstract

Argues that most agent memory today is flat vector RAG, where an agent embeds and chunks data and surfaces the chunks most similar to the task, leaving the model with a pile of text and no sense of how the chunks connect. A context graph instead stores the business as a typed graph: entities (invoice, PO, account, vendor, contract, approver) as nodes; relations (references, draws_on, approved_by) as edges; and one decision trace per real decision (trigger, options considered, why losers lost, constraints, exceptions, decider, reasoning). For each task the agent pulls a small subgraph, leaving the rest out of the context window, which sidesteps context rot. The article stresses that traces must be captured at the moment the decision is made and that human overrides of an agent's choice are the cheapest, highest-signal point to ask why....
