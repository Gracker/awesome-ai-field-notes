# Postgres LISTEN/NOTIFY Actually Scales (DBOS)

> Source: https://www.dbos.dev/blog/postgres-listen-notify-scalability
> Author: DBOS
> Date: 2026-07-25

## Summary (Chinese)

瓶颈在 NOTIFY commit 时拿全局锁到 fsync 完成。DBOS 的解法：通知不做 source of truth，只做 wake-up signal，用内存 buffer 批量 flush，低频 polling 兜底，从 2.9K writes/s 做到 60K writes/s。核心设计原则：通知不做数据源，只做唤醒信号，用内存缓冲区批量刷新。

## Summary (English)

The bottleneck is NOTIFY taking a global lock during commit until fsync completes. DBOS's solution: notifications are not source of truth, only wake-up signals, using in-memory buffer for batch flush, with low-frequency polling fallback. Scaled from 2.9K writes/s to 60K writes/s. Core design principle: notifications as wake-up signals, not data sources.
