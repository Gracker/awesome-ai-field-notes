## 中文导读

Runta 与 Baseten 合作构建了迄今最大规模的 harness 榜单：83B token、27,280 次 agent 运行，覆盖 22 个 harness 配置 × 5 个模型 × 62 个终端任务 × 4 次尝试，规模是 v1.0（9 个 harness、单一 Kimi K3）的 76 倍。核心结论：换模型时就该考虑换 harness——每个模型的性价比最优 harness 都不同：GLM-5.3 配 Codex CLI，GLM-5.3 Flash 配 Pi，DeepSeek V4.1 Flash 1017 配 ZCode，Muse 配 Oh My Pi，Kimi-K3 配 Alma。按单任务成本，中位 harness 的排名在模型间移动了 22 位中的 11 位，Codex CLI 从 GLM-5.3 的第 1 跌到 Kimi-K3 的第 16。

## 为什么值得关注

Harness 选型常被当作与模型无关的工程偏好，这份榜单用 76 倍于 v1.0 的数据把它变成了可量化的成本杠杆：模型解释了单任务成本方差的 92.8%，但在固定模型后，最贵 harness 仍比最便宜的最高贵 1.8–5.0 倍，且成本与通过率的秩相关仅为 −0.39 到 +0.22——多花钱并不换来更高的通过率。对自建 agent 工作流的团队，这是"换模型就重测 harness"的直接依据；对 harness 开发者，结论更具体：砍步骤数（每步重发全部上下文），而不是只压缩 prompt token。

## 关键信息

- 规模：83B token、27,280 次 agent 运行；22 harness 配置（18 个 harness，含 4 个 DeepSeek Harness 工具集 profile 与 OpenCode 两个版本）× 5 模型 × 62 终端任务 × 4 尝试，为 v1.0 的 76 倍
- 模型全部由 Baseten 托管：GLM-5.3、GLM-5.3 Flash、DeepSeek V4.1 Flash 1017、Muse（meta-models/muse-spark-open）、Kimi-K3
- 各模型性价比最优（cost per pass，另设"多花 ≤30% 换 ≥5 分通过率"修正规则）：Codex CLI+GLM-5.3、Pi+GLM-5.3 Flash、ZCode+DeepSeek V4.1 Flash 1017、Oh My Pi+Muse、Alma+Kimi-K3
- 全模型成本/质量前沿只有四个：OpenCode v2（单任务成本最低 $0.561）、Pi、Codex CLI、ZCode（通过率最高 61.9%）；其余 harness 成本最高贵 1.6 倍、通过率 50.6%–60.2%
- 成本方差分解（对数尺度双向方差分析）：模型 92.8%、harness 2.3%、配对+噪声 4.9%；固定模型后 harness 间成本差 1.8–5.0 倍/任务，打乱检验 p=0.003
- 排名漂移：中位 harness 成本排名跨模型移动 11/22 位；Codex CLI 从 GLM-5.3 第 1 到 Kimi-K3 第 16；DeepSeek Harness: Creator 从 Muse 第 1 到 GLM Flash 第 21
- 成本不买质量：各模型成本/通过率秩相关 −0.39 到 +0.22；五个模型中四个的最贵 per-pass harness 通过率反而更低
- 步骤数才是成本主因：steps per pass 与 cost per pass 秩相关 +0.51（p=0.015），而起始 token 数、工具数、缓存命中率均不相关（−0.03 到 +0.02）；每步重发上下文使单次尝试平均消耗 2.0–4.8M 输入 token，最大的首请求（21,365 token）不足其 1%
- 成本构成：缓存命中输入 42%、输出 33%、其他输入 25%；64.5% 的成本花在未通过的运行上（52.7% 失败 + 11.8% 超时）
- 防作弊审计：216 次尝试被标记 reward hacking（其中 163 次为在线查询），均记 0 分
- 五个最优 harness 的共同设计：单一 shell 工具承担 61%–93% 的工具调用、上下文只追加（91%–94% 缓存命中）、不用子代理且几乎不摘要；共同弱点是 68%–82% 的失败运行以自信的最终答案收尾而非超时
- 稳健性：4,000 次任务重抽中 Codex CLI+GLM-5.3 以 99.6% 保持第一，其余四个最优组合置信度仅 25%–53%（多为接近的并列）
- 局限：仅开源模型、单一供应商（Baseten 定价与缓存策略）；下一步计划纳入闭源模型（Claude Opus 5.5、GPT-6 Astra、Gemini 4 Carbon）与长时程任务

## English Summary

Runta partnered with Baseten to build the largest-scale harness leaderboard: 83B tokens across 27,280 agent runs, covering 22 harness configurations × 5 models × 62 terminal tasks × 4 attempts — 76× the size of v1.0, which ranked nine harnesses on Kimi K3 alone. Core finding: when you switch your model, consider switching the harness too. Every model had a different best-value (cost per pass) harness: Codex CLI with GLM-5.3, Pi with GLM-5.3 Flash, ZCode with DeepSeek V4.1 Flash 1017, Oh My Pi with Muse, and Alma with Kimi-K3. By cost per task the median harness moved 11 of 22 rank positions between models, and Codex CLI fell from 1st with GLM-5.3 to 16th with Kimi-K3. A two-way ANOVA on log-scale cost attributes 92.8% of variance to the model, 2.3% to the harness, and 4.9% to the pair/noise; with the model fixed, the priciest harness still cost 1.8–5.0× the cheapest per task. Paying more does not buy pass rate (rank correlation −0.39 to +0.22). Steps per pass — not prompt size, tool count, or cache hit rate — predicted cost per pass (+0.51), since every step resends the whole context (2.0–4.8M input tokens per trial). 64.5% of all cost went to non-passing runs, and 68–82% of failed runs ended with a confident final answer rather than a timeout. Audits flagged 216 reward-hacked trials (163 online lookups), all scored 0.
