## English Excerpts

> GoLand 2026.1.2 made the collecting part easier with a built-in profiler. In GoLand 2026.3, we are taking it a step further – your AI agent can now use that profiler too. You describe the symptom, for example, “reindexing through  POST /reindex  takes much longer than it should, profile it”, and the agent runs your app with the profiler, picks the profiles that fit the problem, reads the results, and points you to the code that is responsible. You do not need to know what a mutex profile is or which  pprof  flags to pass.

> This works with Claude Code, Codex, and Junie through the bundled  goland-profiler  skill and a set of MCP tools. Below, we take a closer look at what the agent does and how you can split the work with it.

> take_profile  Captures a profile (a snapshot, or a CPU profile for a set duration) and returns it with a summary.

> profile_summary  Returns totals and the top 5 functions with their hot lines and call paths, for any saved profile.

> run_with_profiler  Launches a run configuration with the profiler enabled.

> GoLand-started app:  GoLand’s profiler modifies the executable during compilation to expose the profiling API, so it cannot be attached to an already running process. The agent either starts the app through a run configuration with the profiler or works with a session you started yourself.

> Tested agents:  We have tested the workflow with Claude Code, Codex, and Junie. Other agents that can connect to GoLand’s MCP server may work too, but we have not verified them yet.

> Short-lived programs:  The profiler samples a running process, so a CLI tool that finishes in a fraction of a second does not leave enough time to capture anything useful. The skill works best for servers, workers, and other long-running services.

> Three ways to split the work with the agent

## English Summary

GoLand 2026.3 lets your AI agent drive the built-in Go profiler: you describe the symptom (for example, reindexing through POST /reindex takes much longer than it should, profile it), and the agent runs your app with the profiler, picks the profiles that fit the problem, reads the results, and points you to the responsible code, without needing to know mutex profiles or pprof flags. It works with Claude Code, Codex, and Junie through a bundled goland-profiler skill plus MCP tools; the skill tells the agent when to reach for the profiler (slow execution, high CPU, excessive allocations, memory growth, lock contention, goroutine leaks) and explicitly forbids adding net/http/pprof or temporary profiling code, so sources stay untouched. JetBrains reports the agents found the same bottlenecks with about half the tokens.
