## 中文导读

Armin Ronacher 在 Pi 1.0 里给出的 MCP 答案叫 Codemode：工具调用不走『定义进 context、模型挑一个』的老路，而是让模型在 harness 内的沙盒里写 JavaScript，用代码把工具调用组合起来。沙盒实现是 WASM 运行时里的 QuickJS，带刻意的限制：无网络、无文件系统、无 timer、内存受限，代码唯一能做的就是再调一次其他工具。这样做的直接收益是大体量输出可以结构化吞吐，而不必每次把后 2000 行灌回 context；调用之间可以暂存状态，也能并发触发工具。Codemode 在 Pi 里随 MCP 默认启用，也可以在设置里用 defaultTools 的 +codemode 单独打开。文章把这一定位为作者 2025 年 Code Is All You Need 与 MCP needs code 两篇主张的工程落地。

## English Abstract

With Pi 1.0 the author added MCP support via Codemode: instead of loading tool definitions and outputs into context, the model writes JavaScript in a harness-side sandbox (QuickJS in WASM, no network/file system/timers, limited RAM) whose only capability is calling other tools. This lets large outputs be consumed structurally and enables state stash and concurrency; Codemode is on by default in Pi when MCP is enabled.

## English Summary

Codemode replaces context-loaded tool selection with sandboxed JS composition of tool calls in Pi 1.0; the sandbox forbids network, filesystem, and timers so tool calls are the only side channel, and large outputs no longer need to be dumped back into context.
