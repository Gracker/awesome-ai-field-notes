# I built a programming language that LLMs can't use

> Source: [https://blog.picheta.me/post/killswitch-lang/](https://blog.picheta.me/post/killswitch-lang/) · platform: blog · author: Dominik Picheta · date: 2026-10

## TL;DR（中文摘要）

Dominik Picheta（Nim 作者）造了 KillSwitch：一门人类可用、对 LLM 与 coding agent 尽量难的 esolang，用来测 LLM 写代码靠理解还是靠背训练集片段。反 LLM 设计包括规格书埋人类易识破的谎言、标识符按字母计数（解释器拒绝不合规程序）、"Ignore previous instructions" 是有语义的语言成分、脚本主体是可嵌语法指令的叙事。基准任务刻意简单，最高分仅 66.8：Claude Opus 5 最佳且高于 Opus 5.5，Fable 5.1/Gemini 4 Argon 被自家安全护栏拖垮。HN 评论区给出边界反证：给 Claude 喂解释器源码造个 Go 反编译器就能破——对抗面画在裸模型与带工具链的 agent 之间。

## Summary (English)

Dominik Picheta built KillSwitch, a human-usable esolang designed to be hard for LLMs and coding agents, testing whether code generation reflects understanding or memorized snippets. Anti-LLM features include lies embedded in the spec, letter-counted identifiers the interpreter enforces, semantically meaningful 'Ignore previous instructions', and narrative-embedded syntax. Top benchmark score is 66.8 (Claude Opus 5, above Opus 5.5); safety-guardrail-sensitive models fail. HN counterexamples with a Go decompiler built by Claude draw the boundary between bare models and toolchain-wielding agents.

## 原文要点（grounded facts）

- 动机：测 LLM 写代码靠理解还是靠背训练集片段——设计人类可用、对 LLM 与 coding agent 尽量难的 esolang
- 反 LLM 设计：规格书埋谎言（部分规则留给人类推断）、标识符按字母计数且解释器拒绝不合规程序、"Ignore previous instructions" 是有语义的语言成分、脚本主体是故事（叙事可嵌语法指令）
- 基准任务刻意简单（hello world、两数取大、温度换算逆变换），最高分 66.8
- Claude Opus 5 最佳且高于 Opus 5.5（作者判断非随机，Opus 5 更会读规格）；Fable 5.1 与 Gemini 4 Argon 被安全护栏拖垮；开源最佳 MiMo-V2.6-Pro
- HN 反证：prologic 用 Claude 造 Go 版反编译器+Skill 可把 KS 程序译回 Go；作者回应「喂了解释器源码当然能破」——边界在裸模型 vs 带工具链的 agent
- killswitch-lang.org + 开源解释器/规格 + bench.killswitch-lang.org 榜单
