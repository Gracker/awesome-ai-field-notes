English Source Excerpt

TL;DR: I fine-tuned a 360M-parameter language model to act as a terminal. There's no shell or filesystem behind it: every keypress goes in, and the model predicts how the screen changes. It can create files, run vim and tmux, play snake, and usually remembers what you wrote a few commands later. The biggest wins were teaching it to repair its own mistakes and decoding screen rows in parallel.

## English Summary

The author fine-tuned Qwen2.5-Coder-0.5B (about 494M parameters) to emulate a terminal with no shell or filesystem behind it: the model predicts screen deltas on a character grid using a 333-token vocabulary (256 byte tokens, 64 row tokens, a few specials) with grammar-constrained decoding, so every prediction is a valid screen update. Training data is synthetic but exact: 336k episodes (roughly 2B tokens) recorded keypress-by-keypress from real programs inside Docker, with randomized personas, hosts, prompts and terminal sizes. A DAgger-style self-repair loop lifted PresetBench from 24/47 to 38/47 at int4; WorldTUI scores 80/106 on ShellBench versus 52 for the prompted base model and passes 9/13 file readbacks versus 2-3. Dropping the 151,936-entry embedding table cut the model to about 360M parameters, and int4 quantization brought it to 208 MB running fully in-browser via WebGPU (about 60 ms per keypress on an M4 Mac). Parallel per-row drafting cut large-frame p95 latency from 6.7 s to 0.87 s on an RTX 4090, with self-speculative decoding fixing cross-row coordination; distillation ablations showed exact memory depends on individual layers - removing layer 7 collapsed exact readbacks from 64/64 to 0/64, and a 16-layer student that kept layers 1, 7, 15 and 22 passed all memory worlds but lost ShellBench accuracy (65 vs 78).
