## 中文导读

MindStudio 实测 RTX Spark 笔记本装原生 Linux：驱动与外设可跑通，但接电后 GPU 锁在约 780MHz（Windows 约 2.2GHz）。根因是 Windows 独占的 Nvidia Platform Controllers and Framework：电源表加密，只有 Windows 驱动能解密。GPT-OSS-120B 实测：Windows 65.4 tok/s、WSL 65.1、DGX Spark 61、原生 Linux 仅 13.9；统一内存划分仅 Windows 可调。WSL 是现实落点，根治需 Nvidia 把电源管理移植进 Linux 驱动。

## 原文摘录

> GPU clock speed collapses to about 780 MHz on Linux when plugged in, compared to roughly 2.2 GHz on Windows, because the firmware's power table is encrypted and only the Windows driver can decrypt it.
> Benchmarks on GPT-OSS-120B show the gap clearly: Windows hit 65.4 tokens per second, WSL hit 65.1, the Nvidia DGX Spark hit 61, and native Linux on the same laptop managed only 13.9.

## English Summary

MindStudio hands-on (Nov 1, 2026, ed. Luis Chavez-Mattos) on dual-booting Linux on Nvidia RTX Spark laptops (MSI Prestige N16 Flip AI Plus, Asus ProArt, Dell XPS): install and desktop work with GPU acceleration via Nvidia's open kernel driver, but on wall power the GPU locks to ~780 MHz vs ~2.2 GHz on Windows. Root cause: the Windows-only Nvidia Platform Controllers and Framework manages CPU/GPU power delivery with an encrypted power table only the Windows driver can decrypt. GPT-OSS-120B throughput: Windows 65.4 tok/s, WSL 65.1, DGX Spark 61, native Linux 13.9. The 96GB unified-memory GPU reservation split is also Windows-only; WSL is the practical option until Nvidia ports power management to its Linux driver.
