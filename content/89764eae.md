## 中文摘要

微软 ThinkingBox 基准的 HF 官方博文：agent 的完成与否取决于终态而非自我报告。打分对象是 terminal backend state 与副作用，不是回复像不像完成；477/507 题只看状态，模拟用户持私有上下文、被问到才提供。每题独立跑 20 次，报告 pass@1、pass@20 与 20/20 全过三列指标。12 个模型 121,680 次有效尝试中 79,853 次可执行检查失败，其中 67.24% 的失败仍表现为干净结束、调了改状态工具且无显式报错；失败检查里 database hash mismatch 占 98.95%。pass@1 头名 Claude Opus 5.5 为 67.16%，但其 20/20 只有 47.53%——单次成功不等于每次都对。随文开源三仓（MIT 框架、基准数据、RL 训练）并给出本地运行路径。10 月 3 日发布。

## One-liner

ThinkingBox 用 terminal state 与 20 次重复度量 agent 的真实完成与一致性

## English Summary

The official HF blog post for Microsoft's ThinkingBox benchmark: agents are scored on terminal backend state and side effects rather than self-reported completion. 477 of 507 tasks check only final state; a simulated user holds private context and shares it only when asked; each task runs 20 independent times to report pass@1, pass@20, and a literal 20/20 consistency count. Across 121,680 valid trials from 12 models, 79,853 executable checks failed - and 67.24% of those failures still ended cleanly, called state-changing tools, and showed no explicit error; database hash mismatch accounts for 98.95% of failed checks. Top pass@1 is Claude Opus 5.5 at 67.16%, but its 20/20 rate is 47.53%: passing once is not passing every time. Ships as three repos (MIT framework, benchmark data, RL training) with local run instructions.
