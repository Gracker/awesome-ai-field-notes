## 中文导读

Anthropic 工程博客：2026 年 5 月其 monorepo 日均合并约 2500 次代码变更，9 月已超 3 万次/日，瓶颈从写代码转移到为人而建的基础设施（源码管理/构建/CI）。团队用 5 个月自研版本控制系统 Scion 并全面替换 git：主分支历史近 100GB，每日约 2500 万次代码检出，按 git 直连模型相当于每天 600PB 流量。Scion 的核心假设是客户端永远在线：commit/rebase/merge 与 diff/blame 全部在服务端完成，客户端只持有有界缓存与按需稀疏/虚拟化工作副本；changeset 以写前日志+内容寻址 blob 存储，无 packfile，无全局锁，引用仅保留 main 与发布分支。分层缓存检出架构命中率超 99%，基础设施 CPU/内存占用比原 git 镜像集群小 200 倍，检出从分钟级降到秒级，CI 释放 25% CPU。7 人小队同期交付了代码评审系统 Antique；工程师转向意图级评审（负责对 Claude 说不），并用常驻单组件的 Claude「superfan」做细粒度健康监控。

## 为什么值得关注

这是目前最完整的一手案例：当 agent 成为代码的主要作者时，为离线人类设计的 git 分布式模型成为扩容瓶颈。文章给出从原则（客户端永远在线、无 packfile、无全局锁）到实测收益（基础设施占用缩小 200 倍、检出秒级、CI 释放 25% CPU）的完整链条，对自建 agent 开发基础设施的团队有直接参考价值。

## English Summary

As agent-written code pushed merged changes from ~2,500/day (May 2026) to 30,000+/day (September), source control - not coding - became Anthropic's bottleneck. With ~100 GB of main-branch history and ~25 million checkouts per day (~600 PB/day under naive git traffic assumptions), a seven-person team built Scion, an in-house version control system, and fully migrated the monorepo off git in five months. Scion assumes always-online clients: commits, rebases, merges, diff and blame run server-side; clients hold a bounded cache plus sparse/virtualized working copies; changesets live in a write-ahead log with content-addressed blobs - no packfiles, no global locks, and refs limited to main and release branches. A tiered checkout cache (node daemon, regional scion-cache, authoritative scion-server) sustains over 99% hit rates, cut checkout time from minutes to seconds, freed a 25% CPU capacity win in CI, and shrank infrastructure CPU/memory footprint 200x versus the previous git mirror fleet. The same team shipped the Antique code review system; engineers shifted to intent-level review, with per-component Claude "superfans" monitoring service health.
