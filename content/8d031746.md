## English Summary

Android APIs deprecate continuously and migrating usages to recommended replacements is a recurring developer burden. This systematic study analyzes 1,000 deprecated APIs and 4,336 real-world migration commits from GitHub, identifying six migration categories and recurring usage-update patterns: Android-version checks, parameter adaptation, object initialization, data-type conversion, and changes in API interaction mechanisms. Augmenting the zero-shot GUPPY benchmark prompts with the migration category and matching pattern raises correct updates from 139 to 147 of 156 tasks, improving five of six categories. The gains are modest; the durable value is the corpus and the pattern taxonomy, usable directly as checklists for LLM-assisted migration and code review. Accepted at ICECCS 2026.

## Abstract (arXiv)

Android Application Programming Interfaces (APIs) continuously evolve, causing existing APIs to become deprecated and requiring developers to migrate their usages to recommended replacements. Although prior studies have proposed automated migration techniques, their effectiveness is often limited by the diversity and contextual complexity of API changes. This paper presents a systematic study of deprecated Android APIs, their recommended replacements, and real-world usage updates performed by developers. Based on an analysis of 1,000 deprecated APIs and 4,336 migration examples collected from GitHub, we identify six migration categories and derive recurring usage-update patterns involving Android-version checks, parameter adaptation, object initialization, data-type conversion, and changes in API interaction mechanisms. To assess their applicability, we augment the zero-shot GUPPY benchmark prompts with the migration category and corresponding usage-update pattern. On 156 benchmark tasks, the pattern-guided prompt improves correct updates from 139 to 147 and performs better in five of the six categories.
