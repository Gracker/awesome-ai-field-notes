## English Version

Prompt Engineering, also known as In-Context Prompting, refers to methods for how to communicate with LLM to steer its behavior for desired outcomes without updating the model weights.

### Basic Prompting

**Zero-shot** learning is to simply feed the task text to the model and ask for results.

**Few-shot** learning presents a set of high-quality demonstrations, each consisting of both input and desired output, on the target task. As the model first sees good examples, it can better understand human intention and criteria for what kinds of answers are wanted.

**Tips for Example Selection**:
- Choose examples that are semantically similar to the test example using k-NN clustering in the embedding space.
- Select diverse and representative sets using graph-based approaches.
- Use contrastive learning specific to one training dataset for in-context learning sample selection.
- Use Q-Learning for sample selection.

**Tips for Example Ordering**:
- Keep examples diverse, relevant to the test sample, and in random order to avoid majority label bias and recency bias.

### Instruction Prompting

Instead of few-shot examples, why not just give the instruction directly? When interacting with instruction models, describe the task requirement in details, try to be specific and precise.

### Chain-of-Thought (CoT)

Chain-of-thought (CoT) prompting generates a sequence of short sentences to describe reasoning logics step by step, known as reasoning chains or rationales, to eventually lead to the final answer.

**Few-shot CoT**: Prompt the model with a few demonstrations, each containing manually written high-quality reasoning chains.

**Zero-shot CoT**: Use natural language statement like "Let's think step by step" to explicitly encourage the model to first generate reasoning chains.

**Tips**:
- Self-consistency sampling improves reasoning accuracy by sampling diverse answers and taking majority vote.
- Model-generated rationales can replace human-written ones to introduce randomness.
- STaR (Self-Taught Reasoner) method: Ask LLM to generate reasoning chains and only keep those leading to correct answers, then fine-tune on those.

## 中文版

提示工程（Prompt Engineering），也称为上下文提示，是指如何与 LLM 通信以在不更新模型权重的情况下引导其行为以获得期望结果的方法。

### 基础提示

**零样本（Zero-shot）** 学习是简单地将任务文本输入模型并要求结果。

**少样本（Few-shot）** 学习是在目标任务上呈现一组高质量的演示，每个演示都包含输入和期望输出。由于模型首先看到好的示例，它能更好地理解人类意图和想要的答案标准。

**示例选择技巧**：
- 使用嵌入空间中的 k-NN 聚类选择与测试示例语义相似的示例。
- 使用基于图形的方法选择多样化且有代表性的集合。
- 使用针对特定训练数据集的对比学习进行上下文学习样本选择。
- 使用 Q-Learning 进行样本选择。

**示例排序技巧**：
- 保持示例多样化、与测试示例相关，并以随机顺序排列以避免多数标签偏差和近因偏差。

### 指令提示

为什么不直接给出指令而非少样本示例？与指令模型交互时，详细描述任务要求，尽量具体和精确。

### 思维链（CoT）

思维链（Chain-of-Thought）提示生成一系列短句子，逐步描述推理逻辑（称为推理链或理由），最终得出最终答案。

**少样本 CoT**：用几个演示提示模型，每个演示包含手动编写的高质量推理链。

**零样本 CoT**：使用"让我们逐步思考"这样的自然语言陈述来明确鼓励模型首先生成推理链。

**技巧**：
- 自洽采样通过采样多个多样化答案并采用多数投票来提高推理准确性。
- 模型生成的原理可以替代人类编写的原理以引入随机性。
- STaR（自学推理器）方法：要求 LLM 生成推理链，仅保留导致正确答案的推理链，然后在此基础上进行微调。
