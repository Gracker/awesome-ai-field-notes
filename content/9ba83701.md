## 中文导读

PPO、GRPO 这类 RL 后训练里 rollout 采样是算力大头，标准蒸馏流程却把这些轨迹直接扔掉，再用最终 teacher 重新生成数据。这篇 NeurIPS 2026 论文问：存下来的 teacher RL rollout 能不能直接拿来蒸馏学生。直接用不行：naive SFT 蒸不动 canonical 蒸馏，naive DPO 有用但在弱学生上会崩。作者把 rollout 复用当成数据选择问题，用 GRPO 时已记录的元数据解决：按 prompt pass rate 排序，最简单的 prompt 先做 SFT 热启动，再对混合成败的 prompt 做 DPO；每个 prompt 用保存的 teacher log-likelihoods 挑学生能消化的补全。数学推理和 Python 编码、多个模型族的学生上，两阶段配方平均性能与 canonical 蒸馏相当，且数据构建零额外推理成本。

## 为什么值得关注

RL→蒸馏管线里最贵的资源就是 rollout，这篇论文证明这些轨迹不是废料而是现成的蒸馏数据集，改造成本只是数据选择策略。两阶段（易题 SFT 热启动 + 混合成败 DPO）是训练脚本可以立刻套的配方，对正在做模型蒸馏的团队是直接的算力节省。

## English Summary

RL post-training methods such as PPO and GRPO spend substantial compute sampling rollouts, but canonical distillation discards these traces and regenerates data from the final teacher. This NeurIPS 2026 paper asks whether saved teacher RL rollouts can be reused to distill students. Naive reuse fails: SFT on rollouts underperforms canonical distillation, and naive DPO, while performant, is unstable and collapses on weaker students. The authors treat rollout reuse as a data selection problem using metadata already recorded during GRPO: order data by prompt pass rates, warm-start with an SFT phase on the easiest prompts, then run DPO on mixed-success prompts; per prompt, saved teacher log-likelihoods serve as a proxy for selecting student-compatible completions. Across mathematical reasoning and Python coding tasks with students from multiple model families, the two-stage recipe achieves comparable average performance to canonical distillation with no additional inference cost for dataset construction.
