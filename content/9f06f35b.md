## 中文导读

LLM agent 越来越多与其他负载同机部署，但宿主机侧资源画像一直缺数据。AgentLens 跨 10 个框架、11 个对齐编码任务测量：框架身份能解释峰值 RSS 方差的 52.95%，任务身份只有 4.22%；每次工具调用触发的 execve 次数在 MetaGPT 与 CAMEL 之间相差 39 倍；峰值 RSS 与子进程数的 Spearman 相关只有 0.13——内存压力与进程爆炸是两个独立维度，管住一个管不住另一个。控制器把离线框架指纹与在线执行相位信号（API 等待与工具执行交替出现）结合，用 cgroup v2 做内存协调、不改框架内部代码；trace 回放里三组同置组合在 90% 聚合峰值内存预算下，被保护 worker 的 P95 分配延迟保持 5.7-7.1ms，比静态分配好 2.1-2.6 倍。

## English Summary

AgentLens measures host-side resource demands of LLM agents across 10 frameworks and 11 matched coding tasks: framework identity explains 52.95% of peak-RSS variance while task identity explains only 4.22%; execve counts per tool call differ 39x between MetaGPT and CAMEL; peak RSS and subprocess count correlate at just Spearman 0.13 — memory pressure and process explosions are independent axes. Its controller combines offline framework fingerprints with online phase signals (API-wait/tool-exec alternation) and coordinates memory via cgroup v2 without touching framework code; in trace replay under a 90%-of-aggregate-peak memory budget, protected workers hold P95 allocation latency at 5.7-7.1ms, 2.1-2.6x better than static partitioning.
