## 中文导读

容器里的 AI agent 靠开网络连接干活，驱动它的文本可能是恶意的；sidecar 之类加在 agent 与工具之间的控制会被子进程或裸 socket 绕过，审批结果也对不上内核后来打开的连接。Connection Escrow 把每条出站 TCP 在内核 connect() 路径扣住（任何数据包发出前），只靠挂在 pod cgroup 上 98 条指令的 eBPF 程序；节点侧用 socket cookie、进程、可执行文件摘要、cgroup/pod 身份归因，暂存 agent 写出的前几个字节，交由另一容器里持独立密钥的验证器裁决。放行条件是一条签名 verdict 指名 socket cookie 与目的地，过期、重放、迟到一律拒绝。36 项对抗测试在 eBPF 持有点全部通过：伪造 verdict、重绑定、重放、过期、子进程与改名二进制绕行、agent 自连验证器均被扣住；Kubernetes 上 6 个 pod 的 600 条连接逐条管控，放行延迟中位数 4.5ms（策略本身占 24µs）。另一招用 eBPF uprobe 在 TLS 库边界读明文交模型打分，TLS 端到端不破坏、执行器不持密钥。代码已开源。

## English Summary

Connection Escrow parks every outbound TCP connection from a supervised AI-agent pod inside the kernel's connect() path before any packet leaves, using a 98-instruction eBPF program on the pod cgroup. A node-side interceptor attributes connections via socket cookie, process, executable digest and cgroup identity, holds the first bytes the agent writes, and defers to an isolated verifier holding independent keys; release requires a signed verdict naming that socket cookie and destination — stale, replayed or late verdicts are rejected. All 36 adversarial tests pass (forged verdicts, rebinding, child processes, renamed binaries); 600 connections across 6 Kubernetes pods gated with 4.5ms median release latency (24us policy). An eBPF uprobe reads plaintext at the TLS library boundary for model-based scoring without breaking end-to-end TLS. Code open-sourced.
