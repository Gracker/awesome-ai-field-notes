## 中文摘要

Google 11-19 官宣 Gemini Interactions API 的 Tool Retrieval 进入 preview：agent 挂上百工具时不再每轮把全量参数 schema 塞进 prompt，先只放工具名与描述，schema 按需加载（tool_search + defer_loading）。本地调研核对边界：仅 Interactions 支持；stateless 必须回传 signature；无单独计价，但服务端每次 search 会再跑一轮带全量上下文的模型调用，小库或每轮都搜时可能更贵；与 Anthropic、OpenAI 同名机制同构。大工具库 token 结构问题，三家给出同一形状的答案。

## English Summary

Google announced Tool Retrieval in preview for the Gemini Interactions API on Nov 19: instead of sending the full tool library with parameter schemas in every prompt, agents expose tool names and descriptions and load schemas on demand (tool_search with defer_loading), designed to cut input tokens while keeping tool selection accurate as agents scale. Local verification of the docs notes the boundaries: Interactions-only (generateContent unsupported), stateless callers must return the signature, and while there is no separate price item, each server-side search re-runs a model call with full context - small tool libraries or huge contexts searched every turn can end up costlier than static full loading. The mechanism mirrors Anthropic's defer_loading/tool search and OpenAI's tool_search.

## Official post (2026-11-19)

> Tool Retrieval is now in preview in the Gemini Interactions API. Load tool parameter schemas on demand instead of sending your full tool library in every prompt, designed to reduce input tokens and keep tool selection accurate as your agent scales.

## 机制核对（来自本地调研，源：aistudio.google.com/docs/tool-retrieval）

| 项 | 口径 |
|----|------|
| API 边界 | 仅 Interactions API，generateContent 不支持 |
| 机制 | tool_search + defer_loading: true，先只放工具名/描述，参数 schema 按需加载 |
| 每轮 | tools 每轮仍需重发（stateless 必须回传 signature） |
| 计费 | 无单独加价项，但服务端每次 search 会再跑一轮带全量上下文的模型调用；小工具库或上下文大且每轮都搜时可能比静态全量更贵 |
| 同构 | Anthropic defer_loading / tool search、OpenAI tool_search 同构，非 Google 独有发明 |
