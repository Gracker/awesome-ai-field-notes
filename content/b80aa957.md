## 中文导读

2026-10-09 Anthropic 同日推进两条 agent 编排产品线。**Claude Code Projects**：waitlist 全部 Pro/Max 放开（@ClaudeDevs 官宣，帖互动 likes ~8.7k / views ~664k）。一个 project 是一条长期协调对话，Claude 为每件活开 thread；thread 默认 cloud session（关电脑继续跑，本机需求走 Remote Control），入口在 claude.ai/code、桌面端与手机 App（不是终端 CLI/VS Code/JetBrains）。默认 thread = Opus + high effort，Coordinator 默认 low effort；用量与 Claude Code 同一 plan 限额，全账户 projects 合计每天最多 200 个新 thread；project instructions 上限 16k。**Managed Agents dynamic workflows** 进入 public beta（@ClaudeDevs 官宣，likes ~8.9k / views ~521k）：agent type `multiagent_20261001`，主 agent 写 plan 分阶段编排多 agent 后合并；官方自测 116k 行代码藏 70 bugs，单 agent 约 14–27 个，workflow 三次均 66。workflow-runs 官方限额：单 run 生命周期启动 agents ≤1,000（累计上限，非并发；超限 thread_limit_error），同时工作 threads ≤64，run 寿命默认 ≤24h，同 session open runs 默认 ≤10，session budget 创建时设定不可追加。两者同名不同层：Code 文档另有本地 dynamic workflows（会话内脚本跑 subagent），MA workflows 是托管 API 编排，入口/账单/限额都不同。

## 为什么值得关注

读者最容易混淆的点被这两个文档钉死了：侧栏出现 Projects ≠ 账户能跑「一千个 agent」——Projects 是个人订阅上的协调 UI（每天 200 新 thread 上限），MA workflows 才是 API 托管编排（1000 是生命周期累计，并发档约 64）。对做多 agent 编排的团队，这是两条不同的扩容路径：个人级长程协调看 Projects 的 cloud thread + Overview 面板，生产级编排看 `multiagent_20261001` 的 session budget + workflow-runs 限额表。

## 关键信息

- Projects：Pro/Max waitlist 全放开（2026-10-09），日新 thread ≤200，默认 Opus high effort，instructions ≤16k
- Projects thread 默认 cloud session；GitHub cloud thread 需要 Claude GitHub App（仅 /web-setup token 不够）
- MA workflows：`multiagent_20261001`，启动 agents ≤1000/生命周期，并发工作 threads ≤64，open runs ≤10，run 寿命 ≤24h
- MA 自测：116k LOC 藏 70 bugs，单 agent 14–27 vs workflow 66（token 消耗大，建议小任务起步）
- 同名陷阱：Code 本地 dynamic workflows 与 MA dynamic workflows 同名不同层
