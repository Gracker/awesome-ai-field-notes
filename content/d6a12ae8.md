# Hermes Agent v0.22.2: gateway-after-reboot fix after wrong-commit 0.22.1

> 原文链接: https://github.com/NousResearch/hermes-agent/releases/tag/v0.22.2

## 要点 (中文)

官方发版说明承认 0.22.1 从错误 commit 构建，带入未发布的 gateway 改动，Microsoft Store 应用可能卡在 Connecting；0.22.2 是 0.22.1 本应成为的版本（2026-10-15）。核心修复：重启后 supervised gateway（systemd/launchd/Docker）拒绝启动——Linux 可能把早期 PID 分配给无关进程，gateway 误判已有实例；现在记录启动所在 boot，无法判断时询问只有存活 gateway 才持有的 host lock（#138594，修复 #133744）。已知问题：0.22.1 gateway 下运行的会话在 0.22.2 无法删除。

## Key claims (English)

Hermes Agent v0.22.2 is the release 0.22.1 was meant to be: 0.22.1 was built from the wrong commit and shipped unreleased gateway work (Microsoft Store app could stick on Connecting). v0.22.2 fixes the supervised gateway refusing to start after reboot by recording its boot and consulting a host lock only a live gateway holds (#138594, fixes #133744). Known issue: sessions that ran under the 0.22.1 gateway cannot be deleted.

# Hermes Agent v0.22.2

**Release Date:** October 15, 2026

v0.22.1 was built from the wrong commit. It shipped unreleased gateway work, and the Microsoft Store app could stick on "Connecting." 0.22.2 is the release 0.22.1 was meant to be.

> **Known issue:** Sessions that ran under the 0.22.1 gateway can't be deleted in 0.22.2.

## Highlights

- **The gateway starts after a reboot again.** After a restart, Linux can hand an early PID to an unrelated process, and the gateway could mistake it for a running gateway, so a supervised gateway (systemd, launchd, Docker) refused to start. Hermes now records the boot it started in, and when it can't tell, it asks the host lock, which only a live gateway holds. ([#138594](https://github.com/NousResearch/hermes-agent/pull/138594), fixes [#133744](https://github.com/NousResearch/hermes-agent/issues/133744))
- **Long local-model turns survive on laptops.** Local requests always stream with prompt-reading progress (shown in the status line), stall timers skip time the machine was asleep, a recovered local server gets another try instead of a breaker that failed every later message, and compression no longer times out while the server is still reading a long conversation.
