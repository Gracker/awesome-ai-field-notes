## 中文导读

针对软件工程 agent 的运行时防御：现有轨迹分析只看初始 prompt 和工具调用序列，看不到环境里真正执行了什么。AgentBouncer 在系统调用层做动态仲裁——agent 经工具触发的每个 syscall 都经过一个 LLM arbiter，沿必要性和安全性两轴判断：不安全的拒绝，且调用越不必要，放行所需的安全置信度越高；预置策略规则和层级感知缓存把 LLM 仲裁限制在关键决策上以控制开销。在 340 个开发环境攻击（4 类向量）加 SWE-bench Verified 良性任务上，攻击成功率从无监督 agent 的 99.41% 降到 10.59%，比对比的 SOTA 防御低 18.23–73.53 个百分点；良性任务成功率不受损，仅 0.25% 良性工具调用失败；每任务只加 47 秒和 0.0036 美元 LLM 成本，而最接近的同类运行时防御要 4.5 倍时间和 9.6 倍成本。

## English Summary

AgentBouncer is a runtime enforcement system for software-engineering agents that mediates, and when necessary denies, the system calls agents trigger via tool calls, closing the gap left by trajectory analysis that inspects only the initial prompt and tool-call sequence but not what actually executes in the environment. An LLM arbiter judges each syscall along two axes, necessity and safety; unsafe calls are denied, and the less necessary a call appears, the more safety certainty is required to allow it. Preseeded policy rules and hierarchy-aware caching invoke the arbiter only for key decisions. On 340 attacks against the development environment across four vectors plus benign SWE-bench Verified tasks, the attack success rate drops from 99.41% (unsupervised agent) to 10.59%, 18.23-73.53 percentage points below competitive defenses, while task success is preserved (only 0.25% of benign tool calls fail), at 47 seconds and USD 0.0036 per benign task versus 4.5x the time and 9.6x the cost for the closest existing runtime defense.
