## 中文导读

WorkOS 发布开放协议 auth.md：应用在自己域名下放置一个 Markdown 文件，声明 agent 如何代用户注册——支持哪些流程、有哪些 scope、如何签发凭证。两条注册流程：agent verified 由 agent 的身份提供方担保用户身份（无人在环），user claimed 由 agent 展示确认码、用户登录确认（无提供方也可用）。凭证是绑定用户的短时效、可撤销的 scoped access token，走标准 OAuth（组合 Protected Resource Metadata 与 ID-JAG），不绑定 WorkOS 基础设施，任何应用可发布、任何 agent 可读取。Cloudflare、Neon、Firecrawl、Resend、Parallel、monday.com 等已在各自域名上线 auth.md。agent 代注册从「模拟人类填表」走向机器可读的一等协议。

- 凭证：绑定用户的短时效、可撤销 scoped access token，走标准 OAuth（Protected Resource Metadata + ID-JAG）
- 开放性：协议不绑定 WorkOS 基础设施；任何应用可发布、任何 agent 可读取；协议仓库 github.com/workos/auth.md

## English Summary

WorkOS published auth.md, an open protocol for agent registration: apps host a Markdown file at their domain telling agents which flows, scopes and credentials they support for registering users on a user's behalf. Two flows: agent verified (the agent's identity provider vouches for the user, no human in the loop) and user claimed (the agent shows a code, the user confirms sign-in; no provider needed). Agents receive short-lived, revocable scoped access tokens over standard OAuth, composing Protected Resource Metadata and ID-JAG identity assertions; the protocol is not tied to WorkOS infrastructure - any app can publish and any agent can read one. Cloudflare, Neon, Firecrawl, Resend, Parallel and monday.com already serve auth.md at their domains.

## FAQs

-   What is auth.md?

    A Markdown file an application hosts at its domain — typically `https://yourapp.com/auth.md` — that tells agents how to register on behalf of a user. It includes which flows are supported, which scopes exist, and how to register for the service. [See the file format](https://workos.com/auth-md/docs/auth-md).

-   How does an agent register a user with my app?

    The agent fetches your `auth.md`, picks a supported flow, and either presents a verified identity assertion (agent verified flow) or walks the user through a code-confirmation claim (user claimed flow). You stay in control of which flows you accept and what credentials get issued. [Read the apps guide](https://workos.com/auth-md/docs/apps).

-   What's the difference between the agent verified and user claimed flows?

    Agent verified is agent-attested — the agent's identity provider vouches for the user, no human in the loop. User claimed needs no provider — the agent shows the user a code, they sign in and confirm it. Most apps support both and let the agent pick the right one. [Agent verified](https://workos.com/auth-md/docs/flows/verified) · [User claimed](https://workos.com/auth-md/docs/flows/claimed).

-   What credentials get issued to the agent?

    A scoped access token tied to the user — short-lived and revocable. It's issued over standard OAuth, so you reuse the API auth you already have.

-   Is auth.md a WorkOS only feature or an open protocol?

    It's open. WorkOS authors the protocol, but `auth.md` isn't tied to WorkOS infrastructure — it composes existing OAuth standards (Protected Resource Metadata, ID-JAG identity assertions) and any app can publish or any agent can read one with no WorkOS account required. [See the protocol on GitHub](https://github.com/workos/auth.md).
