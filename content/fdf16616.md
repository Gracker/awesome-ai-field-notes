## 中文导读

统一内存设备上 GPU 跑 LLM 推理、CPU 跑本地检索时，4 个并发检索 worker 会把 p95 decode 延迟推高 60-61%（两台 M4 系统），prefill 只涨 5.7-6.9%。PhaseGate 把 LLM 推理相位当作 CPU 检索的准入信号，给 prefill 与 decode 分别校准检索并发上限（基础 M4 配置为 4 和 1），积压队列下聚合检索吞吐达到最好固定策略的 2.0 倍，同时 7 次 held-out 运行的 p95 LLM 延迟全部压在无检索基线的 1.25 倍以内；不观察相位的对照策略吞吐相近，但每次都超出输出 token 延迟线。M2 与 M2 Pro 上策略排序一致。已获 NeurIPS 2026 On-Device Intelligence workshop 接收。

## 为什么值得关注

端侧 LLM 的检索调度从静态配额换成相位准入：decode 相位对带宽最敏感这一测量，直接适用于 Android 统一内存设备的 NPU/CPU 争抢场景。

## English Summary

On unified-memory devices running GPU LLM inference alongside CPU retrieval, four concurrent retrieval workers raise p95 decode latency by 60-61% while prefill rises only 5.7-6.9%. PhaseGate uses LLM inference phase as an admission signal for CPU retrieval, calibrating concurrency caps per phase (4 for prefill, 1 for decode on the base M4): backlog-drained aggregate retrieval throughput reaches 2.0x the best fixed policy while p95 LLM latency stays within 1.25x of the no-retrieval baseline across 7 held-out runs; phase-blind controls match throughput but violate output-token latency every time. Policy ordering is consistent on M2 and M2 Pro. Accepted at the NeurIPS 2026 On-Device Intelligence workshop.
