## 中文版

### Vibe Coding 的快乐与痛苦

Karpathy 在构建 MenuGen 时，经历了典型的 AI 开发者的两极体验：

**本地 Demo 阶段（令人振奋）：**
- 用 LLM 写代码飞快，边做边聊，想法即时成真
- 没有生产环境的包袱，可以随意试错
- "Vibe coding"让人感受到软件 3.0 时代的创造力解放

**线上产品阶段（痛苦跋涉）：**
- 部署、认证、支付、数据库、安全、域名——每一项都是独立的服务
- 这些"无聊但必须"的部分消耗了远超代码本身的时间
- 从本地 demo 到真正可用的产品，中间隔着一整个 DevOps 学习曲线

### 核心观察

> "当我在大约一年前构建 menugen 时，我发现最难的部分绝对不是代码本身，而是你要像组装 IKEA 家具一样把一大堆服务拼凑起来才能让它真正运行。"

### 为什么这很重要

| 维度 | LLM 擅长 | LLM 不擅长 |
|------|---------|-----------|
| 代码生成 | 极快 | 需要调试 |
| 架构决策 | 有洞见 | 需要经验 |
| 部署/DevOps | 不擅长 | 需要大量知识 |

**Vibe Coding 降低了"写代码"的门槛，但没有降低"做产品"的门槛。** 从零到本地 Demo 容易，从 Demo 到 production 难。

### 给 AI 原生开发者的启示

1. 不要等到"代码写完"才开始考虑 DevOps
2. 优先掌握"足够好"的部署能力：Vercel/Supabase/Railway 等 BaaS 可以大幅降低门槛
3. 认证和支付是最难的部分，建议用成熟方案（Clerk、Stripe）
4. AI 不会让你跳过系统设计的经验积累，但可以加速每个具体步骤

## English Version

### The Joy of Vibe Coding, The Pain of Production

When Karpathy built MenuGen, he experienced the classic AI developer's bipolar journey:

**Local Demo Phase (Exhilarating):** Writing code with LLMs is fast, no production burdens, free to experiment.

**Deployed Product Phase (Painful Slog):** Deployment, authentication, payments, database, security, domain names—each is an independent service consuming far more time than the code itself.

### Core Observation

> "When I built menugen ~1 year ago, I observed that the hardest part by far was not the code itself, it was the plethora of services you have to assemble like IKEA furniture to make it real."

### Why This Matters

**Vibe Coding lowered the barrier to "writing code," but not to "making products."** From zero to local demo is easy; from demo to production is hard.

### Implications

1. Don't wait until "code is done" to think about DevOps
2. Use BaaS platforms (Vercel/Supabase/Railway) to reduce deployment barriers
3. Use mature solutions for auth and payments (Clerk, Stripe)
4. AI accelerates each step but won't replace system design experience
